# pm-spa-design

## 核心约束

1. **技术栈**：Vue3 CDN + TailwindCSS + Ant Design Vue。页面必须是单文件 HTML，可直接在浏览器打开。
2. **组件优先级**：优先使用 Ant Design Vue 的成熟组件，如 `a-button`、`a-input`、`a-select`、`a-table`、`a-form`、`a-tabs`、`a-modal`、`a-drawer`、`a-upload`、`a-tag`、`a-alert`、`a-pagination`。自定义 `.tos-*` 组件只做布局、业务卡片和视觉补充。
3. **主色**：`#42b7ae`。每页只使用这一套主色，主色只用于主按钮、当前态、关键链接、聚焦边框和少量关键图标。
4. **功能色**：成功 `#52c41a`、警告 `#faad14`、错误 `#f5222d`，仅用于状态、风险、反馈和删除动作。
5. **视觉风格**：清爽、克制、专业、适合后台系统。禁止花哨渐变、彩色大块、装饰插画、强阴影、过度圆角、卡片套卡片。
6. **圆角**：页面卡片/弹窗 12px，按钮/输入框/选择器 8px，标签 4px。不要使用胶囊形大圆角，除非是头像、开关或圆形图标按钮。
7. **阴影**：默认少用阴影，优先用浅边框分层。卡片阴影最多 `0 4px 16px rgba(15, 23, 42, 0.04)`。
8. **间距**：页面外边距 20px，卡片内边距 20px，表单项间距 16px，紧凑区 8px。信息密度要稳定，不要为了“好看”拉得过空。
9. **响应式**：桌面优先 12 栅格/左右布局；小屏自动单列。标题、按钮、表格、卡片文字不得溢出或互相遮挡。
10. **第一屏原则**：业务工具页面第一屏直接展示可操作内容，不做营销式 hero，不写功能说明大段文案。
11. **H5 页面左侧菜单**：生成会员端/消费者端 H5 页面时，必须包含左侧固定导航菜单（`position:fixed; left:0`，200px 宽，纯 `<a href>` 跳转），方便在桌面浏览器中切换查看多个 H5 页面。H5 容器 414px `margin:0 auto` 居中。详细模板见 `references/page-templates.md` 第 8 节。

## 工作流程

### 第一步：读取规范

生成或修改页面前，必须先参考：

- `references/design-system.md`
- `references/component-examples.html`
- `references/page-templates.md`

如果用户指定了已有页面，还要先阅读该页面的结构、现有 class、脚本依赖和交互绑定，避免破坏已有逻辑。

### 第二步：澄清需求（信息不足时）

只在信息不足以动手时提问，最多 3 个：

- 页面类型：列表、详情、表单、看板、工作台
- 核心模块：2-5 个最关键业务模块
- 必要交互：弹窗、抽屉、批量操作、上传、导入导出、状态流转

### 第三步：页面设计顺序

1. 页面结构：顶部栏、内容容器、必要侧栏或底部操作栏
2. 业务主流程：表单、表格、看板、上传区或详情区
3. 操作区：主操作唯一突出，次操作弱化
4. 边界状态：加载、空态、错误、禁用、只读、成功反馈
5. 响应式：桌面和 390px 小屏都要可用

### 第四步：组件质量要求

- 表单：标签短、必填清晰、错误信息贴近字段，长表单按业务分组。
- 表格：列头浅灰、行高稳定、操作列靠右，危险操作用文字按钮或确认框。
- 卡片：只承载一组业务信息，不把页面区块都做成浮动卡片。
- 按钮：同一区域只保留一个主按钮；普通操作用次按钮或文本按钮。
- 标签：状态标签用功能色；普通分类标签用灰阶。
- 上传：使用虚线边框、浅背景、明确空态，不使用夸张图标或彩色块。
- 弹窗/抽屉：标题、内容、底部操作分区清楚，按钮顺序稳定。

### 第五步：代码质量

- HTML：语义清晰，结构层级少，避免无意义包裹。
- CSS：优先 Tailwind 和 Ant Design Vue；自定义样式用 `.tos-*` 命名，集中放在 `<style>` 中。
- JS：只模拟必要数据和交互，不引入无关业务复杂度。
- 文案：中文、短句、业务化，不写“功能强大”“智能高效”等营销文案。

### 第六步：视觉自检

完成前必须检查：

- 首屏非中性色不超过 3 种。
- 没有紫色、蓝色、粉色等非 TOS 高饱和装饰色。
- 主色面积克制，没有大面积铺底。
- 卡片、表单、按钮圆角统一。
- 文字不溢出，按钮不换行挤压，移动端无横向滚动。

## 输出

- 输出完整 HTML 代码，文件名建议：`tos_页面名称_v1.0.html`。
- 修改已有文件时，保持原有业务逻辑和脚本绑定，优先做局部、可验证的改动。

你可以通过启动退款并收听通知来部分或全部偿还客户之前的交易。

开始使用

有时，客户会在交易成功后提出付款请求。有时，付款后无法履行订单。无论哪种情况，你都需要考虑是否应该启动：

  1. 部分退款或，
  2. 全额退款

我们的退款API接口允许你部分或全部偿还你的客户。你只需发起退款请求，我们就会及时向你通报退款状态。

创建退款

要发起退款，你可以向 创建退款 API 发出 POST 请求，并传递交易 ID 或 transaction 字段中的引用。如果金额未通过，我们将按全额退款处理该请求。

如果你想进行部分退款，请传递 amount 参数以及退款金额。退款金额不得超过原交易金额。

curl https://api.paystack.co/refund
-H 'authorization: Bearer YOUR_SECRET_KEY'
-H 'cache-control: no-cache'
-H 'content-type: application/json'
-d '{ "transaction":"qufywna9w9a5d8v", "amount":"10000" }'
-X POST

重试退款

当你发起退款时，通常会使用成功付款时从处理通道返回的客户银行账户详细信息进行处理。如果客户的银行账户未退回，退款状态将变为needs-attention。这基本上意味着你需要提供客户的银行账户详细信息才能继续处理退款。你可以通过调用 重试退款API 接口来完成此操作：

#!/bin/sh
url="https://api.paystack.co/refund/retry_with_customer_details/{id}"
authorization="Authorization: Bearer YOUR_SECRET_KEY"
content_type="Content-Type: application/json"
data='{
"refund_account_details": {
"currency": "NGN",
"account_number": "1234567890",
"bank_id": "9"
}
}'

curl "$url" -H "$authorization" -H "$content_type" -d "$data" -X POST

账户详细信息可以是属于客户的任何有效银行账户，并且可以与用于进行初始付款的账户不同。

仅当你收到 refund.needs-attention Webhook 事件时才使用此接口。否则，接口返回422 - 无法处理的实体响应。

退款状态

在退款的生命周期中，其状态根据退款处理者执行的操作而变化。当退款状态发生变化时，关联交易的状态也会随之变化。

下表显示了退款状态与其关联交易之间的关系：

状态描述交易状态
pending退款已启动，正在等待处理者的响应撤销待决
processing处理者已收到退款。撤销待决
needs-attention你需要提供客户的银行详细信息才能继续退款。撤销待决
failed退款处理失败，你的账户现在反映了存入的金额。成功
processed处理者已成功处理退款。反转

当退款标记为processed时，客户可能仍需要最多 10 个工作日才能收到资金。

收听通知

我们根据退款状态发送不同的事件。你可以监听以下事件以了解客户退款状态的最新信息：

活动描述
refund.pending当发起退款并且我们正在等待处理者的响应时发送此信息。
refund.processing当处理者收到退款时发送此信息。
refund.needs-attention当我们需要帐号来完成退款时会发送此信息。
refund.failed当无法处理退款时发送此信息。退款金额已存入你的账户。
refund.processed当处理者成功处理退款时发送此信息。

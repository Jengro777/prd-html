InlineJS 库提供了一系列方法，允许你在 Web 应用程序中受理支付。

简介

InlineJS 是 Paystack 的 JavaScript 库，为 Web 应用程序提供简单、安全且方便的支付流程。它提供了启动不同类型支付的方法，例如一次性、循环、拆分等，并处理支付状态，所有这些都只需几行代码。

浏览器支持

Paystack InlineJS 旨在支持所有最新版本的主要浏览器。该库被编译为 ES5 并进行了polyfilled，以确保它可以在尽可能多的设备上运行。

我们不支持 IE9 等过时的浏览器，也不支持 Opera mini 等禁用 JavaScript 的浏览器。

  • 我们要求浏览器支持TLS 1.2
  • 我们在所有平台上支持 Chrome 和 Safari
  • 我们在 Android 4.4 及更高版本上支持 Android 本机浏览器

我们不支持 Opera Mini，因为其中禁用了 JavaScript。但是，我们支持 Opera 浏览器，但在超级保护模式下，JavaScript 也被禁用。

安装

Paystack InlineJS 可以通过 CDN、NPM 或 Yarn 包含在你的应用程序中：

<script src="https://js.paystack.co/v2/inline.js">

如果你通过NPM或Yarn安装，请先导入库。类名也从 PaystackPop(CDN) 更改为 Paystack（NPM 或 Yarn）：

const popup = new PaystackPop();

薪资对象

Paystack 对象提供对 InlineJS 中可用方法和接口的访问。它公开了方法以及配置选项，可以帮助你在 Web 应用程序中无缝受理支付。 Paystack对象暴露的方法包括：

  1. checkout(options)：这是一个用于创建交易的异步方法。
  2. newTransaction(options)：这是用于创建交易的同步方法。
  3. resumeTransaction(accessCode)：使用此方法，你可以使用初始化接口从后端发起交易，然后在前端完成交易而无需重定向。
  4. cancelTransaction(id)：有时，加载交易可能需要一段时间。在这种情况下，可以使用此方法取消交易。
  5. preloadTransaction(options)：此方法用于在后台加载交易，以便当用户即将结账时，Popup立即加载。
  6. paymentRequest(options)：当用户可以通过钱包（例如 Apple Pay）进行付款时，这最适合处理自定义用户体验

paymentRequest()目前仅支持Apple Pay。除非另有说明，本文档中所有提及钱包的内容均指 Apple Pay。 Paystack 还通过 checkout() 自动支持 Google Pay。

回调

交易请求

使用Paystack，可以针对不同场景发起交易，例如：

  • 一次性付款
  • 多笔分割支付

InlineJS提供参数和方法来创建不同类型的交易。下表显示了创建交易时使用的常规选项：

选项类型必填描述
key字符串真实你的公钥，从 Settings > API Keys & Webhook 中的 Paystack 仪表板获取
amount数量真实以你的货币的最低面额计算的交易金额
email字符串真实客户的邮箱地址
currency数量错误交易的货币。你可以查看所有支持的货币的API参考
firstName字符串错误客户的名字
lastName字符串错误客户的姓氏
phone字符串错误客户的电话号码
customerCode字符串错误有效的 Paystack 客户代码。如果提供，这将覆盖上面的所有客户信息
channels数组错误一系列可供使用的支付渠道。可用频道有['card', 'bank', 'ussd', 'qr', 'eft', 'mobile_money', 'bank_transfer', ‘apple_pay’]
metadata对象错误你想要保存到交易中的额外信息的有效对象。
reference字符串错误唯一区分大小写的交易参考。仅允许使用 -、.、= 和字母数字字符。

一次性交易

使用InlineJS最基本的方式是接受一次性交易的付款。一般来说，付款是非循环性的，不需要特殊配置。我们提供两种接受一次性付款的方法：

  1. 新交易（选项）
  2. 结账（选项）

新交易（选项）

这是用于创建交易的同步方法。它最适合不需要使用异步流的情况。它采用所有常规交易请求选项，并且可以如下所示使用：

  • 新交易（选项）
const popup = new Paystack()

popup.newTransaction({
key: 'pk_domain_xxxxxx',
email: 'sample@email.com',
amount: 23400,
onSuccess: (transaction) => {
console.log(transaction);
},
onLoad: (response) => {
console.log("onLoad: ", response);
},
onCancel: () => {
console.log("onCancel");
},
onError: (error) => {
console.log("Error: ", error.message);
}
})

结账（选项）

与其对应部分类似，但用于异步流程。它采用所有常规交易请求选项，并且可以如下所示使用：

  • 结账（选项）
const popup = new Paystack()

popup.checkout({
key: 'pk_domain_xxxxxx',
email: 'sample@email.com',
amount: 23400,
onSuccess: (transaction) => {
console.log(transaction);
},
onLoad: (response) => {
console.log("onLoad: ", response);
},
onCancel: () => {
console.log("onCancel");
},
onError: (error) => {
console.log("Error: ", error.message);
}
})

付款请求

付款请求用于处理 Apple Pay 等钱包付款。它用于通过使钱包选项在你的网站上更加突出来创建自定义体验。例如，你可以有一个 Apple Pay 按钮和另一个用于加载结账的按钮。

loadPaystackCheckoutButton字符串错误打开结账表单按钮的ID
styles对象错误钱包按钮的CSS样式

styles 对象采用以下选项：

选项类型必填描述

选项类型必填描述

恢复交易

恢复交易流程允许你在服务端上发起交易并在浏览器中完成它。此流程既提供了服务端初始化的安全性，又提供了浏览器中用户体验的便利性。首先，从后端向 初始化交易API 接口发出 POST 请求：

curl https://api.paystack.co/transaction/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com",
"amount": "500000"
}'
-X POST
{
  "status": true,
  "message": "Authorization URL created",
  "data": {
    "authorization_url": "https://checkout.paystack.com/nkdks46nymizns7",
    "access_code": "nkdks46nymizns7",
    "reference": "nms6uvr1pl"
  }
}

在返回的响应的data对象中，你需要保存access_code并将其发送到前端。

不要直接在你的移动应用程序上向初始化交易接口发出 API 请求，因为它需要你的密钥。你的密钥只能在可以采取更强安全措施的服务端上使用。

恢复交易（访问代码）

在你的前端，你可以使用这个access_code来完成支付而无需离开你的网站。

选项类型必填描述
accessCode字符串真实交易初始化返回的访问代码
  • 恢复交易（访问代码）
const popup = new Paystack()

popup.resumeTransaction(access_code)

resumeTransaction方法触发浏览器中的结账，允许用户选择自己喜欢的支付渠道来完成交易。

分割交易

有时你需要与其他企业或实体共享交易。为此，你可以在设置付款时从响应中传递创建子账户并传递subaccoutCode：

const popup = new Paystack()

popup.newTransaction({
key: 'pk_domain_xxxxxx',
email: 'sample@email.com',
amount: 45000,
subaccountCode: 'ACCT_dskvlw3y3dsvkmt',
onSuccess: (transaction) => {
console.log(transaction);
},
onLoad: (response) => {
console.log("onLoad: ", response);
},
onCancel: () => {
console.log("onCancel");
},
onError: (error) => {
console.log("Error: ", error.message);
}
})

下表显示了可用于配置拆分付款的参数：

选项类型必填描述
subaccountCode字符串真实有效的 Paystack 子账户代码，例如 ACCT_8f4s1eq7ml6rlzj
bearer字符串错误这用于指定承担 Paystack 费用的账户。值可以是 account 或 subaccount（默认为 account）。
transactionCharge数量错误主账户应收取固定费用（以你货币的最小面额计算）。这会覆盖创建子账户时设置的分割百分比。

多分割交易

多分割支付用于与多个合作伙伴共享单一交易。根据你的用例，可以通过 API 提前创建拆分，也可以在交易启动期间动态创建拆分。

如果你提前确定了你的分割配置，你可以在设置交易时创建分割并传递split_code：

  • 多分割交易
const popup = new Paystack()

popup.newTransaction({
key: 'pk_domain_xxxxxx',
email: 'split@dynamic.com',
amount: 35650,
currency: 'NGN',
split: {
type: 'percentage',
bearer_type: 'account',
subaccounts: [
{
subaccount: 'ACCT_dskvlw3y3dsvkmt',
share: 30
},
{
subaccount: 'ACCT_eg4sob4590pq9vb',
share: 20
}
]
},
onSuccess: (transaction) => {
console.log(transaction);
},
onLoad: (response) => {
console.log("onLoad: ", response);
},
onCancel: () => {
console.log("onCancel");
},
onError: (error) => {
console.log("Error: ", error.message);
}
})
选项类型必填描述
split_code字符串真实有效的 Paystack 拆分代码，其中包含如何与合作伙伴拆分付款的配置

否则，你可能希望通过在交易请求中传递 split 对象来动态创建分割：

  • 多分片动态交易
const popup = new Paystack()

popup.newTransaction({
key: 'pk_domain_xxxxxx',
email: 'multi@split.com',
amount: 98540,
split_code: 'SPL_RYUUL4u1hP',
onSuccess: (transaction) => {
console.log(transaction);
},
onLoad: (response) => {
console.log("onLoad: ", response);
},
onCancel: () => {
console.log("onCancel");
},
onError: (error) => {
console.log("Error: ", error.message);
}
})
选项类型必填描述
type字符串真实采用 flat 或 percentage 来指示你想要固定份额还是可变份额
bearer_type字符串真实用于指示交易费用的承担者。它采用以下值之一：all、all-proportional、account或subaccount
subaccounts数组真实获取用于指定账户和每个账户的份额的子账户对象数组
bearer_subaccount字符串错误持有者的子账户代码。如果bearer_type是subaccount则应指定
reference字符串错误拆分的唯一参考

订阅

订阅允许你为客户处理定期计费。第一次设置付款时，你可以添加以下参数，告诉我们持续向客户收费：

选项类型必填描述
planInterval字符串真实计划的间隔。有效间隔为 daily、weekly、monthly、annually
subscriptionLimit数量错误本次订阅的收费次数
subscriptionStartDate字符串错误订阅的开始日期（第一次收费后）
const popup = new Paystack()

popup.newTransaction({
key: 'pk_domain_xxxxxx',
email: 'sub@main.com',
amount: 20000,
planInterval: 'weekly',
onSuccess: (transaction) => {
console.log(transaction);
},
onLoad: (response) => {
console.log("onLoad: ", response);
},
onCancel: () => {
console.log("onCancel");
},
onError: (error) => {
console.log("Error: ", error.message);
}
})

请求中指定的金额将随后用于订阅。

或者，你可以创建计划通过 API或仪表板并在交易请求中传递planCode：

const popup = new Paystack()

popup.newTransaction({
key: 'pk_domain_xxxxxx',
email: 'plan@email.com',
amount: 40000,
planCode: 'PLN_l6aglbqzebn32c6',
onSuccess: (transaction) => {
console.log(transaction);
},
onLoad: (response) => {
console.log("onLoad: ", response);
},
onCancel: () => {
console.log("onCancel");
},
onError: (error) => {
console.log("Error: ", error.message);
}
})
选项类型必填描述
planCode字符串真实有效的 Paystack 计划代码，例如 PLN_cujsmvoyq2209ws
subscriptionCount数量错误为此计划创建的订阅数量

虽然金额是必需参数，但订阅计划时用于创建计划的金额优先。

预加载交易

预加载交易与创建新交易类似，但有一点不同。你可以提前加载交易，而不是等到最后一刻才发出交易请求。

此方法在 Popup 上加载交易，而无需打开它。它返回一个可用于稍后打开 Popup 的函数。这使得 Popup 在用户准备付款时立即加载。

预加载交易（选项）

此方法采用交易请求的所有常规选项：

<button id="make-payment">Make Payment</button>
const popup = new Paystack()

const loadPopup = popup.preloadTransaction({
key: 'pk_domain_xxxxxx',
email: 'testuser@paystack.com',
amount: 10000,
currency: "NGN"
});

document.querySelector("#make-payment").onclick = loadPopup;

取消交易

在某些情况下，你想要构建取消交易的逻辑。 cancelTransaction 方法允许你取消交易并隐藏结账 iFrame。

取消交易（id）

选项类型必填描述
id字符串真实要取消的付款交易ID
const popup = new Paystack()

const transaction = popup.newTransaction({
key: 'pk_domain_xxxxx',
email: "demo@example.com",
amount: 10000,
onLoad: (transaction) => {
window.clearInterval(redirectTimer);
}
});

let timeElapsed = 0;
const timeLimit = 2;
const redirectURL = 'https://your.redirecturl.com';
const redirectTimer = setInterval(() => {
timeElapsed += 1;
if (timeElapsed === timeLimit) {
popup.cancelTransaction(transaction.id);
window.location.href = redirectURL;
}
}, 1000);

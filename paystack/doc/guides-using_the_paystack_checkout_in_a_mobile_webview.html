当你在移动应用程序中使用 Paystack 受理支付时，有两种方法可以实现：

  1. 使用为你选择的技术堆栈构建的 Paystack 库 - 你可以使用我们的移动设备 SDK 将 Paystack 直接集成到你的 Android 或 iOS 应用程序中。对于 Ionic 或 React Native 等移动框架，请查找库 这里。
  2. 使用网络视图 - 你还可以生成结账 URL 并将其嵌入到移动应用程序的 WebView 中。我们将在本指南中介绍此选项。

出于本指南的目的，我们将包含使用 Flutter、React Native、本机 Android 和 iOS 构建的移动应用程序的示例代码，但所描述的流程适用于所有移动应用程序开发堆栈

为什么使用 WebView？

考虑在 WebView 中使用托管结账而不是直接与移动设备 SDK 集成有不同的原因。无论你选择哪种方式，付款仍然由相同的底层APIs处理。唯一的区别是你将为客户提供的支付体验。使用 WebView 的一些优点是：

  1. 通过使用我们的托管结账，整个支付体验均由 Paystack 控制。这意味着你不必在移动应用程序中构建结账UI来受理支付，因此在你的应用程序中集成付款所需的代码更少。
  2. 虽然手机SDK上只能使用银行银行银行卡支付，但所有其他非银行银行银行卡支付类型（例如银行转账、USSD、Visa QR、移动货币和银行支付）都可以在结账时使用，因此可供客户使用。

如果你不使用 WebView，你仍然可以在移动设备上通过卡受理支付。所有频道均可直接在 API 上使用，并且可以集成到你的应用程序中。

生成结账URL

集成的第一步是初始化交易以获取结账URL。

当客户单击付款操作按钮时，通过从你的服务端向我们的 API 发出 POST 请求来初始化交易。将邮箱、金额和任何其他可选参数传递给初始化交易API 接口。

curl https://api.paystack.co/transaction/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com", "amount": "20000",
"callback_url":"https://hello.pstk.xyz/callback",
"metadata":{"cancel_action": "https://your-cancel-url.com"}
}'
-X POST
{
  "status": true,
  "message": "Authorization URL created",
  "data": {
    "authorization_url": "https://checkout.paystack.com/nkdks46nymizns7",
    "access_code": "nkdks46nymizns7",
    "reference": "nms6uvr1pl"
  }
}
参数描述
amount金额应采用支持货币的子单位
email客户的邮箱地址
callback_url可选的URL，客户在成功付款后将被重定向到。如果你不添加，客户将被重定向到 Paystack 仪表板中设置的回调 URL。
metadata自定义数据的字符串化 JSON 对象。
metadata.cancel_action可选的URL，当客户点击结账页面上的取消按钮时，将被重定向到该页面。如果你不添加该小部件，客户将保留在结账 Web 视图中，直到你关闭该小部件。

有关可以传递的参数的完整列表，请参阅初始化交易API 接口。

在 WebView 中显示结账

如果API调用成功，Paystack会在响应中返回授权URL。将这个 URL 返回到前端应用程序，并将其加载到 Webview 小部件中。请参阅下面的示例代码：

@override
Widget build(BuildContext context) {
return Scaffold(
body: WebView(
initialUrl: 'https://checkout.paystack.com/7zu1ot06d0qn9h6',
javascriptMode: JavascriptMode.unrestricted,
userAgent: 'Flutter;Webview',
),
);
}

需要在 WebView 中启用 JavaScript 才能正确加载结账。

UIWebView 在 iOS 12.0 中已被弃用，因此在本指南中我们将使用 WKWebView。

我们假设你想要在其中显示结账的视图控制器的故事板中有 WKWebView。

在 WebView 中加载结账后，你需要监听客户操作。换句话说，你需要知道客户何时完成支付或关闭结账页面。这可以通过在 WebView 小部件中侦听 URL 重定向来完成。

处理 WebView 重定向

WebView 小部件中应允许重定向，以允许银行和 3DS 授权。如果 WebView 阻止重定向，客户将无法完成交易。

当客户成功完成支付后，他们将被重定向到 Paystack 仪表板中设置的回调 URL。但是，你可以通过在初始化交易时传递 callback_url 来覆盖这一点。这将覆盖仪表板上设置的回调 URL，并且客户将被重定向到那里。 WebView 小部件现在应该如下所示

@override
Widget build(BuildContext context) {
return Scaffold(
body: WebView(
initialUrl: 'https://checkout.paystack.com/7zu1ot06d0qn9h6',
javascriptMode: JavascriptMode.unrestricted,
userAgent: 'Flutter;Webview',
navigationDelegate: (navigation) {

if (navigation.url == "https://hello.pstk.xyz/callback") {
verifyTransaction(reference);
Navigator.of(context).pop();
}
if (navigation.url == "https://your-cancel-url.com") {

Navigator.of(context).pop();

}
return NavigationDecision.navigate;
},
),
);
}

如果你实现了 Webhook，charge.success 事件将发送到你的 Webhook URL，建议你使用它来为后端的客户提供价值。

在你的前端中，检测到 WebView 重定向到回调 URL 后，这意味着交易成功。你可以通过调用 校验交易API 来确认状态，然后你可以以编程方式关闭 WebView 小部件并在应用程序中向客户显示交易确认页面。这是在 verifyTransaction() 方法中处理的。

正确处理 3DS

对于需要3DS身份校验的卡交易，当客户完成授权后，他们将被重定向到https://standard.paystack.co/close。当URL点击https://standard.paystack.co/close时，它应该自动关闭页面。这就是网络浏览器上发生的情况。

但是，使用 WebView 时，页面不会自动关闭。这是因为在浏览器窗口中关闭页面的 JavaScript 函数 window.close() 无法在 WebView 上运行。 WebView 是原生小部件，window.close() 方法只能关闭使用 window.open() 方法打开的窗口。解决方法是让你的 WebView 监听 URL 何时被重定向到 https://standard.paystack.co/close，然后通过检查回调函数和任何其他进程继续照常处理。

@override
Widget build(BuildContext context) {
return Scaffold(
body: WebView(
initialUrl: 'https://checkout.paystack.com/7zu1ot06d0qn9h6',
javascriptMode: JavascriptMode.unrestricted,
userAgent: 'Flutter;Webview',
navigationDelegate: (navigation){
if(navigation.url == 'https://standard.paystack.co/close'){
Navigator.of(context).pop();
}
if(navigation.url == "https://hello.pstk.xyz/callback"){
Navigator.of(context).pop();
}
return NavigationDecision.navigate;
},
),
);
}

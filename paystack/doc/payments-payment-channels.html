API 变更日志

Paystack 使你能够接受使用不同支付渠道的客户的付款，例如：银行卡、移动货币账户、QR代码、直接从他们的银行账户或USSD。

如果你使用Popup或重定向方法，付款客户将看到你在仪表板上选择的所有付款方式。但如果你不想使用任何一个选项，你可以使用 充电API 直接从你的服务端启动所有不同的支付渠道。

银行银行卡支付渠道适用于所有 Paystack 账户，而其他支付渠道仅适用于受支持的国家/地区。

卡片

卡是许多国家常见的支付渠道之一。我们在各个市场支持以下卡：

卡市场
签证全部
万事达卡全部
神韵尼日利亚
美国运通卡尼日利亚、南非和肯尼亚

API 卡适用于我们所有市场中PCI 符合 的企业。如果你打算使用此API，你应该检查下面概述的合规性要求并联系我们。

卡片 API 允许你通过自定义结账安全、合规地将卡片详细信息发送到我们的服务端。有了这个，PCI-DSS投诉企业可以在不影响安全性的情况下构建定制的结账体验。

卡详细信息的敏感性要求企业遵守支付卡行业数据安全标准 (PCI-DSS)，以确保它们得到安全处理。 Paystack 遵循PCI 1 级服务提供商，允许非投诉企业使用我们的Checkout 和手机SDK 进行银行银行卡支付

合规要求

PCI-DSS认证文件只能由经认可的合格的安全评估员（QSA）审核后代表PCI理事会签发。

理事会颁发的文件为合规证明（AOC）和合规报告。，这些文件自签署之日起仅一年内有效。我们要求你先提交这些文件，然后才能使用此API。

对于 Paystack，有效的 AOC 需要显示以下内容：

  1. 经QSA审核后签发
  2. 由 QSA 签署
  3. 自发行之日起一年内
  4. 封面上有 PCI SSC 标志
  5. 至少遵循 PCI-DSS 版本 3.2.1

如果你满足上述条件，请将你的文件提交给support@paystack.com或通过你的Paystack关系经理，我们将授予对APIs的访问权限。

银行账户

此功能目前可供尼日利亚的企业使用。

通过银行付款功能，客户可以通过网上银行门户或提供银行帐号并使用发送到手机或邮箱的OTP进行身份校验来付款。

这与银行转账不同，银行转账是客户将资金转入银行账户。

收集银行详细信息

要收集银行详细信息，你需要提示用户选择银行并输入帐号。要获取支持的银行列表，请使用附加过滤器 pay_with_bank=true 向 列出银行API 接口发出 GET 请求。

银行可以以下拉列表或任何其他格式列出，允许用户轻松选择他们选择的银行。

创建费用

将email、amount、metadata、bank（包含银行的code和客户提供的account_number的对象）和birthday发送到我们的Chargeendpoint开始。

curl https://api.paystack.co/charge
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com",
"amount": "10000",
"bank": {
"code": "057",
"account_number": "0000000000"
}
}'
-X POST
{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "z8q981z5kp7sfde",
    "status": "send_birthday",
    "display_text": "Please enter your birthday"
  }
}

如果选择的银行是Kuda，则需要在bank对象中使用phone和token代替account_number：

当调用API时，data.status键的值为pending，因为支付正在后台处理。然后，根据交易是否成功，data.status更新为success或failed。

通过转账支付

此功能目前仅适用于尼日利亚和加纳的企业。

转账付款 (PwT) 是一项功能，允许商户或企业创建临时银行账户，客户可以使用该账户来支付商品或服务费用。帐号已生成并与当前客户的交易相关联。客户交易后或超过有效期后，帐号将失效。

创建 PwT 费用

在付款时，你向 创建电荷 API 接口发起请求，并传递 email、amount 和 bank_transfer 对象。 bank_transfer对象采用account_expires_at，用于设置交易帐号的到期时间：

#!/bin/sh

url="https://api.paystack.co/charge"
authorization="Authorization: Bearer YOUR_SECRET_KEY"
content_type="Content-Type: application/json"
data='{
"email": "another@one.com",
"amount": "10000",
"bank_transfer": {
"account_expires_at": "2025-04-24T16:40:57.954Z"
}
}'

curl "$url" -H "$authorization" -H "$content_type" -d "$data" -X POST
{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "kcvu0t3kzs",
    "status": "pending_bank_transfer",
    "display_text": "Please make a transfer to the account specified",
    "account_name": "TEST-MANAGED-ACCOUNT",
    "account_number": "1260257501",
    "bank": {
      "slug": "test-bank",
      "name": "Test Bank",
      "id": 24
    },
    "account_expires_at": "2025-04-24T16:40:57.954Z"
  }
}
银行转账参数类型描述
account_expires_at字符串账户有效期，格式为ISO 8601 (YYYY-MM-DDThh:mm:ssZ)。最短时间为距当前时间 15 分钟，最长时间为距当前时间 8 小时。你还可以将其设置为 null，以便我们自动将其设置为距离当前时间 8 小时。

如果 account_expires_at 与当前时间之间的差异为 不到15分钟，我们将默认为 15分钟。如果account_expires_at和当前时间超过8小时之间存在差异，我们将默认为8小时。

如果你需要控制你的企业收到的转账，你应该实施入境转账审批。这使你能够根据你的各种业务需求拒绝或接受转账。

USSD

此付款方式专门针对尼日利亚客户。尼日利亚银行提供客户用来执行交易的USSD服务，我们已与其中一些银行集成以帮助客户完成支付。

通过 USSD 支付渠道允许你的尼日利亚客户通过在移动设备上拨打 USSD 代码向你付款。该代码通常采用* followed by some code and ending with #的形式。系统会提示用户使用 PIN 校验交易，然后确认交易。

发起 USSD 收费所需的只是客户邮箱和收费金额。

当用户付款时，回复将发送至你的Webhook。因此，为了使其按预期正常工作，必须在 Paystack Dashboard 上设置Webhook。

创建费用

将邮箱和金额发送至充电API 接口，并使用你要收费的 USSD 类型。下表显示了支持的类型。

银行类型
担保信托银行737

移动货币

此功能仅适用于加纳、肯尼亚和科特迪瓦的企业。

移动货币渠道允许你的客户使用支持移动货币的电话号码向你付款。付款时，客户需要在手机上授权付款。

由于付款是离线完成的，因此你需要有一个Webhook URL，我们将使用它来将付款的最终状态发送到你的服务端。

创建费用

要发起移动货币收费，你需要向 充电API 发出 POST 请求，并传递客户的 email、amount 和 mobile_money 对象：

curl https://api.paystack.co/charge
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "amount": 100,
"email": "customer@email.com",
"currency": "GHS",
"mobile_money": {
"phone" : "0551234987",
"provider" : "mtn"
}
}'
-X POST

上面的示例代码展示了如何向任何 MoMo 提供商收费。你只需 更改货币 并将 mobile_money 对象中的 mtn 替换为下表中所示的任何其他提供程序代码。

以下是受支持的移动货币提供商的字符代码：

提供商代码国家
MTNmtn加纳和CIV
ATMoney 和 Airtel Moneyatl加纳和肯尼亚
电信公司vod加纳
M-PESAmpesa肯尼亚
橙色orangeCIV
波waveCIV

当你发起请求时，响应包含一个值为 pay_offline 的 data.status 字段。系统还会提示客户在手机上授权交易。你应该向客户显示 data.display_text，然后监听 charge.success Webhook 事件。客户需要在180秒内完成交易，超过后交易失败。这是网络提供商设置的限制。

以下是要求客户离线完成该流程的示例响应：

{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "8nn5fqljd0suybr",
    "status": "pay_offline",
    "display_text": "Please complete authorization process on your mobile phone"
  }
}

如果 180 秒后没有收到 charge.success Webhook 事件，则应调用 校验交易API 接口来获取交易失败的状态和原因，可在响应中的 data.message 参数中找到。

M-PESA

M-PESA 允许肯尼亚企业向个人客户和 M-PESA Till 号码收费。

使用M-PESA，商户可以通过向提供的号码发送STK推送来向个人用户收费。我们建议你在电话号码中包含国家/地区代码。例如，0722000000 应作为 +254722000000 发送到 充电API 接口。系统将提示客户输入PIN以完成交易。

{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "8nn5fqljd0suybr",
    "status": "pay_offline",
    "display_text": "Please complete authorization process on your mobile phone"
  }
}

离线选项允许企业创建稍后完成的充电API。这对于在服务完成后提供付款的企业非常有用，例如：餐馆、电子商务商店、送货和物流服务。客户将向 Paystack 的 Paybill 付款，生成的 account_reference 将识别该交易。对企业的另一个好处是交易不会以错误的金额完成。它会失败，客户将不得不重新开始。

curl https://api.paystack.co/charge
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "amount": 100,
"email": "customer@email.com",
"currency": "KES",
"mobile_money": {
"phone": "254700000000",
"provider" : "mpesa_offline"
}
}'
-X POST
{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "e6i9ak3rbq982wh",
    "status": "pay_offline",
    "display_text": "Please complete authorization process on your mobile phone",
    "account_number": "4084333",
    "account_reference": 1234567
  }
}

acount_number 是付款单编号，而 account_reference 唯一标识交易。如果你需要更改金额，你应该创建新的费用并与客户分享新的详细信息。错误的金额将导致交易失败。

你还可以通过其他企业的 M-PESA Till 号码获得付款。 mobile_money 对象应将 provider 设置为 mptill，并将 account 设置为其他业务的 M-PESA 提单编号。他们将在分配收银台的电话上收到授权提示。

curl https://api.paystack.co/charge
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "amount": 100,
"email": "customer@email.com",
"currency": "KES",
"mobile_money": {
"account" : "1234567",
"provider" : "mptill"
}
}'
-X POST

M-PESA Till 和个人都要求客户在手机上授权交易。因此，在构建自定义体验时，你应该向他们展示 display_text 值。

{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "jq3psd5n96sprwl",
    "status": "pay_offline",
    "display_text": "Please complete authorization process on your mobile phone"
  }
}

由于 M-PESA 交易是异步发生的，因此不容易捕获由于客户错误而导致的故障。当需要很长时间才能完成时，我们建议你实施校验交易。

EFT

EFT支付是一种即时银行转账支付方式，客户通过网上银行界面向商户付款。当开发人员指定 EFT 提供商时，我们会重定向到提供商平台，客户在其中提供其付款详细信息，然后授权付款。

此功能仅适用于南非客户。

创建费用

你需要将email、amount、currency和EFT提供者发送到充电API接口：

curl https://api.paystack.co/charge
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"amount": 5000,
"currency": "ZAR",
"email": "customer@email.com",
"eft": {
"provider": "ozow"
}
}'
-X POST
{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "18c0ywb63zutno0",
    "status": "open_url",
    "url": "https://crayon.paystack.co/eft/EFT_OZOW/121502"
  }
}

Ozow 是目前唯一可用的提供商。

处理响应

当用户完成支付时，将向商户的Webhook发送响应。商户需要设置Webhook来获取支付状态。付款成功后会引发 charge.success 事件。

使用 Pesalink 支付

此功能适用于注册的肯尼亚企业。你需要联系 support@paystack.com 进行启用。

Pesalink 通道使客户能够从其银行平台进行即时转账。每笔交易都有一个帐号和说明或原因，供你的客户在完成支付时使用。

帐号有效期为25分钟。你需要将此超时传达给客户以避免任何对帐问题。 钻石信托银行 (DTB)账户的客户无法通过此渠道进行转账。

创建费用

在付款时，你向 充电API 接口发起请求，并传递 email、amount 和 bank_transfer 对象。 bank_transfer 对象采用 account_expires_at 参数，该参数可以是 null 或距离 UTC 中的当前时间小于 25 分钟。

如果 account_expires_at 与当前时间 超过25分钟 之间存在差异，则默认变为 25分钟。

#!/bin/sh

url="https://api.paystack.co/charge"
authorization="Authorization: Bearer YOUR_SECRET_KEY"
content_type="Content-Type: application/json"
data='{
"email": "user@example.com",
"amount": "10000",
"bank_transfer": {
"account_expires_at": "2025-04-24T16:40:57.954Z"
}
}'

curl "$url" -H "$authorization" -H "$content_type" -d "$data" -X POST
{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "kcvu0t3kzs",

QR代码

QR 代码付款仅适用于南非的企业。它适用于 快照扫描 和 扫码支付支持的应用程序

QR渠道生成QR代码，允许客户在其移动应用程序上完成支付。当客户扫描代码时，他们会在支持的应用程序上进行身份校验以完成支付。

当他们完成交易时，charge.success 事件将发送到你的 Webhook URL。你需要在服务端上实现Webhook来接收事件并更新你的客户。

创建费用

将邮箱和金额以及qr对象发送到充电API接口。 qr 对象应将 provider 参数设置为 scan-to-pay。

curl https://api.paystack.co/charge
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "amount": 1000,
"email": "customer@email.com",
"currency": "ZAR",
"qr": {
"provider" : "scan-to-pay"
}
}'
-X POST
{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "48rx32f1womvcr4",
    "status": "pay_offline",
    "qr_code": "0002010216421527000104176552045499530356654031005802NG5920Babafemi enterprises6005Lagos62230519PSTK_104176000926|16304713a",

  }
}

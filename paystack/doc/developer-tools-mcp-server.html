MCP 服务端测试版

Paystack MCP 服务端使 AI 助手能够使用模型上下文协议与整个 Paystack APIs 进行交互。

MCP 服务端目前处于公共预览版。如果你在使用过程中遇到任何问题或有建议，你可以创建一个问题告知我们或打开一个PR添加功能。

简介

模型上下文协议 (MCP)是一个开放标准，允许AI助手连接到外部工具和数据源。 Paystack MCP 服务端使用此标准将整个 Paystack API 暴露给使用 Paystack OpenAPI 规范 的 AI 代理。

![图片 1：显示 Paystack MCP 服务端如何工作的图片](https://paystack.com/docs/static/e0b90b9a7cdbc1eed4060e5e09ccd754/61583/paystack_mcp_architecture.png)

服务端通过 OpenAPI 解析器动态发现所有可用的 API 接口，并通过一组工具访问它们。这意味着MCP已准备好所有记录的APIs，你可以使用自然语言与Paystack集成进行交互，而无需编写代码或参考文档。

要求

在设置 MCP 服务端之前，请确保你具备以下条件：

  • Node.js v18 或更高版本
  • npm 或纱线

开始使用

使用 npx 安装并运行服务端：

npx @paystack/mcp-server --api-key sk_test_your_key_here

配置选项

你可以通过两种方式提供你的 API 密钥：

方法用途
CLI参数（推荐）--api-key sk_test_...
环境变量设置PAYSTACK_TEST_SECRET_KEY

仅允许测试键 (sk_test_*)。服务端在启动时校验这一点并拒绝实时密钥，以防止实时集成发生意外操作。

它是如何运作的

服务端通过以下工具和资源公开 Paystack API：

工具

工具描述
get_paystack_operation通过操作ID获取操作详细信息（方法、路径、参数）
make_paystack_request执行 Paystack API 请求

资源

资源URI描述
paystack_operation_listpaystack://operations/list列出所有可用的 Paystack 操作及其详细信息
paystack_skillpaystack://skill包含 API 文档、代码片段和最佳实践的知识资源。

示例

当你向助手询问诸如“获取我的 Paystack 业务的最后 5 笔交易”之类的问题时，幕后会发生以下情况。

1.助手浏览操作 它读取paystack_operation_list 来查找与你的请求匹配的操作。响应列出了每个操作；相关资源将如下所示：

{
  "transaction_list": {
    "name": "List Transactions",
    "path": "/transaction",
    "method": "get",
    "queryParameter": [
      {
        "name": "perPage",
        "description": "Records per page"
      },
      {
        "name": "page",
        "description": "Page number"
      },
      {
        "name": "status",
        "description": "Filter by status"
      }
    ]
  }
}

2. 助手获取完整的操作详细信息。 一旦选择了transaction_list，它就会调用get_paystack_operation工具来确认确切的方法、路径和参数，然后再发出请求。

{ "operation_id": "transaction_list" }

{
"name": "List Transactions",
"method": "get",
"path": "/transaction",
"queryParameter": [
{ "name": "perPage", "required": false },
{ "name": "page", "required": false },
{ "name": "status", "required": false }
]
}

3. 助手执行请求。 它使用操作详细信息调用 make_paystack_request 工具，将参数 (perPage=5) 作为查询字符串附加到路径。服务端对 Paystack 进行 API 调用并返回响应。

{
"request": {
"method": "GET",
"path": "/transaction?perPage=5"
}
}


{
"status": true,
"message": "Transactions retrieved",
"data": [
{ "id": 4099260516, "reference": "re4lyvq3s3", "amount": 50000, "currency": "NGN", "status": "success" },
{ "id": 4099260517, "reference": "qa1b2c3d4e", "amount": 120000, "currency": "NGN", "status": "success" }

],
"meta": { "total": 1284, "perPage": 5, "page": 1 }
}

4. 助理回复。 它使用来自 API 的响应来生成用户友好的摘要：

Here are your last 5 transactions:
1. NGN 500.00 — customer@example.com (success)
2. NGN 1,200.00 — another@example.com (success)
…

客户整合

Paystack MCP 服务端可与任何 MCP 兼容的客户端配合使用。将以下配置添加到客户端的 MCP 配置文件中。如果你已在本地克隆并构建服务端，请使用本地构建设置。

  • 托管 (npx)
{
  "mcpServers": {
    "paystack": {
      "command": "npx",
      "args": [
        "@paystack/mcp-server",
        "--api-key",
        "sk_test_..."
      ]
    }
  }
}

When using command: "node", ensure you're running Node v18 or later. If you use a version manager, you might need to provide the full path to your Node binary. Run which node on macOS/Linux or where node on Windows to get the path.

及时推荐

为了在使用 MCP 服务端时获得最佳结果，请在提示中具体说明并始终在请求中包含“Paystack”。服务端提供内置指令，帮助AI助手找到正确的API详细信息。

好的提示：

  • “初始化 50000 NGN 的 Paystack 交易”
  • “在我的 Paystack 账户上使用邮箱 user@example.com 创建客户”
  • “我如何使用 Paystack API 汇款？”
  • “向我展示一个用于校验 Paystack 交易的 cURL 示例”

不太有效的提示：

  • “列出我的交易”（不清楚使用哪个服务）
  • “向客户收费”（缺少有关 Paystack 的上下文）

一个好的提示包括：你想要做什么、你需要哪个 Paystack 功能或接口，以及任何特定参数。这有助于助手从 Paystack API 中选择正确的操作，而无需猜测。

故障排除

问题解决方案
服务端在启动时静默退出检查 PAYSTACK_TEST_SECRET_KEY 是否已设置或者你是否传递了 --api-key 标志
“无效密钥”错误密钥必须以 sk_test_ 开头不允许使用实时密钥
工具未出现在客户端中确保服务端正在运行并且客户端配置路径正确
请求超时检查与 api.paystack.co 的网络连接，并确保你的防火墙或代理设置不会阻止请求

有关更多信息，请查看 GitHub 上的 Paystack MCP 服务端存储库。

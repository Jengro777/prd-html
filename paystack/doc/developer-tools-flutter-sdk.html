Flutter SDK 测试版

Flutter SDK 提供了允许你在 Flutter 应用程序中受理支付的方法和模型。

Flutter SDK 目前是测试版。如果你在使用过程中遇到任何问题或有建议，你可以创建一个问题告知我们或打开一个PR添加功能。

简介

Paystack Flutter SDK 提供了允许开发人员为其 Flutter 应用程序构建安全、便捷的支付流程的方法。集成过程分为两步：

  1. 在服务端上发起交易
  2. 在 SDK 上完成

此流程的好处是你可以将密钥远离客户端，这是一种安全的标准做法。

项目要求

Paystack Flutter SDK 采用了 Android 和 iOS 中的最新模式，这限制了我们可以支持的这些操作系统的旧版本。使用 Flutter SDK 进行构建时，请确保你的项目满足以下要求：

  • Flutter >= 3.0.0
  • iOS >= 13
  • Android：最小 SDK - 23 和编译 SDK - 34

目前，下面的Flutter 3.3.0扩展了FlutterActivity作为Android的基类。 FlutterActivity 没有 ComponentActivity，这是在其祖先树中使用 SDK 加载支付视图的必需条件。要解决此问题，请将项目的 Android 文件夹中的 MainActivity 中的 FlutterActivity 更改为 FlutterFragmentActivity。

开始使用

要将 PaystackFlutter SDK 添加到你的项目中，请在终端中运行以下命令：

flutter pub add paystack_flutter_sdk

此命令将 paystack_flutter_sdk 添加到 pubspec.yaml 文件中的包依赖项，并安装它以供在项目中使用。要使用该库，请将其导入到你的 .dart 文件中，如下所示：

import 'package:paystack_flutter_sdk/paystack_flutter_sdk.dart';

初始化交易

SDK 需要 access_code 来显示受理支付的 UI 组件。要获取 access_code，请从服务端向 初始化交易API 接口发出 POST 请求：

curl https://api.paystack.co/transaction/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com",
"amount": "500000"
}'
-X POST
{
  "status": true,
  "message": "Authorization URL created",
  "data": {
    "authorization_url": "https://checkout.paystack.com/nkdks46nymizns7",
    "access_code": "nkdks46nymizns7",
    "reference": "nms6uvr1pl"
  }
}

交易成功初始化后，你会收到包含 access_code 的响应。你需要将此access_code返回到你的移动应用程序。

不要直接在你的移动应用程序上向初始化交易接口发出 API 请求，因为它需要你的密钥。你的密钥只能在可以采取更强安全措施的服务端上使用。

薪资堆栈类

Paystack 类提供了在应用程序中管理付款的方法。将 SDK 导入到你的项目中后，你需要初始化此类以访问其方法：

final _paystack = Paystack();

Paystack 类具有以下方法，可通过其实例使用：

  • 初始化（）
  • 发射（）

初始化（）

此方法允许你设置SDK如何运行的配置。方法签名是：

Future<bool> initialize(String publicKey, bool enableLogging)

它是一个异步方法，返回布尔值并接受以下参数：

参数类型必填描述
publicKey字符串是的这是从 Paystack Dashboard 获取的公钥。它应该是与用于初始化交易的密钥相关联的密钥。
enableLogging布尔值否用于指示你是否想要获取Android和iOS平台的日志。

这是使用 initialize 方法的示例：

String publicKey = "pk_domain_xxxxxx";

try {
final response = await _paystack.initialize(publicKey, true);
if (response) {
log("Sucessfully initialised the SDK");
} else {
log("Unable to initialise the SDK");
}
} on PlatformException catch (e) {
log(e.message!);
}

发射（）

此方法用于完成你之前在服务端上初始化的交易。它加载你的客户在完成支付时与之交互的付款UI。方法签名是：

Future<TransactionResponse> launch(String accessCode)

它是一个异步方法，返回 TransactionResponse 并接受以下参数：

参数类型必填描述
accessCode字符串是的这是交易初始化请求响应中的access_code。

这是使用 launch 方法的示例：

String reference = "";

try {
final response = await _paystack.launch(_accessCode);
if (response.status == "success") {
reference = response.reference;
log(reference);
} else if(response.status == "cancelled") {
log(response.message);
} else {
log(response.message);
}
} on PlatformException catch (e) {
log(e.message!);
}

当你的集成正确完成后，你将需要处理 TransactionResponse 模型。但是，在某些情况下你可能会遇到一些集成错误。异常用于处理Paystack类方法中的集成错误，全部合并到PaystackException模型中。以下部分描述如何处理 TransactionResponse 和 PaystackException。

交易响应

当你成功集成SDK并能够获得付款UI时，将返回TransactionResponse模型。它与交易生命周期相关并具有以下参数：

参数类型描述
status字符串指示交易的状态。可能的值为：successcancelledfailed。
message字符串这是有关交易状态的简短详细信息。
reference字符串这是用于管理后支付流程的唯一标识符。仅当status为success时才返回。

Paystack异常

在集成过程中会引发异常。主要存在开发过程方面的问题。 PaystackException 使用特定于平台的 FlutterError 模型，该模型具有以下参数：

参数类型描述
code字符串这表明错误的类别。
message字符串这是错误的简短描述。
details字符串目前返回nil。在将来的更新中，我们可以使用它来提供有关修复错误的详细信息。

这意味着你可以解析任何异常，如下所示：

try {
final response = await _paystack.launch(_accessCode);

} on PlatformException catch (e) {
log(e.code!);
log(e.message!);
}

以下是PaystackException返回的错误码：

错误代码描述
INVALID_ARGUMENT当你没有传递设置 SDK 所需的参数时，就会发生这种情况。
INITIALIZATION_ERROR当无法使用传递的参数初始化 SDK 时，就会发生这种情况。
UNSUPPORTED_VERSION当你的项目不符合 SDK 要求时，就会发生这种情况。
MISSING_VIEW当 SDK 找不到要附加的视图控制器 (iOS) 或 Activity (Android) 时，就会发生这种情况。
LAUNCH_ERROR当付款UI无法加载时会发生这种情况。

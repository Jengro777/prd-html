将自定义数据添加到你的请求负载

使用元数据，你可以添加接口自然不接受的其他参数。制作元数据将取决于你的语言对 JSON 的处理。常见的元数据有：

  • Payment medium (site/app)

向元数据对象添加参数有两种方法：

  1. Key/value pair：你将参数作为键和值对传递，如下所示：cart_id: IU929。通过这种方式传递的参数不会显示在仪表板上，但是，它们会随 API 响应返回。
  2. 自定义字段：custom_fields 键是为一组自定义字段保留的，当你单击交易时，这些字段应显示在仪表板上。

自定义字段有 3 个键：display_name、variable_name 和 value。显示名称将是显示时值的标签。

{
  "metadata": {
    "cart_id": 398,
    "custom_fields": [
      {
        "display_name": "Invoice ID",
        "variable_name": "Invoice ID",
        "value": 209
      },
      {
        "display_name": "Cart Items",
        "variable_name": "cart_items",
        "value": "3 bananas, 12 mangoes"
      }
    ]
  }
}

取消操作

当用户取消付款时，你可以将他们重定向到所选的 URL。这是通过在元数据中设置 cancel_action 来完成的：

"metadata": {
"cancel_action": "https://your-cancel-url.com"
}

定制过滤器

自定义过滤器允许你通过使用 metadata 对象中的 custom_filters 对象来控制交易的完成方式。

定期付款

如果你将来需要向客户借记，请在 custom_filters 对象中指定 recurring=true。

"metadata": {
"custom_filters": {
"recurring": true
}
}

卡和银行支付 (PwB) 通道支持此功能，每个通道具有不同的行为。

通过 card 渠道，我们仅接受支持定期计费并强制对 MasterCard 和 VISA 进行银行身份校验的 Verve 卡。

通过pwb渠道，我们只会向客户提供支持的银行进行付款。不支持定期付款的银行将被过滤掉。

精选银行卡

当你只想接受特定银行卡进行交易时，可以使用 banks 参数指定银行代码。你可以使用 列出银行 API 获取支持的银行代码列表。

"metadata": {
"custom_filters": {
"banks": ["057", "100"]
}
}

精选卡品牌

如果你只希望交易接受某些卡品牌，请在 card_brands 数组中指定品牌：

"metadata": {
"custom_filters": {
"card_brands": ["visa"]
}
}

我们目前支持以下卡品牌：

过滤器也可以组合起来形成综合规则。在下面的代码片段中，过滤器告诉我们客户应该注册定期计费，并且我们应该只接受来自 真力时 (057) 或 阳光信托银行 (100) 的 Visa 卡。

{
  "metadata": {
    "custom_filters": {
      "recurring": true,
      "banks": [
        "057",
        "100"
      ],
      "card_brands": [
        "visa"
      ]
    }
  }
}

选定的银行账户

supported_bank_providers 参数允许你在 通过银行支付 通道上指定所需的库。设置后，客户将只能看到你指定的银行。你应该使用 列出银行 API 接口来获取银行代码。

"metadata": {
"custom_filters": {
"supported_bank_providers": [
"033",
"215",
"102"
]
}
}

选定的 MoMo 提供商

有时，你只想优先考虑某些移动货币提供商。例如，你可能希望开展一项活动以仅允许某个提供商。为此，你可以在 supported_mobile_money_providers 参数中指定提供程序：

"metadata": {
"custom_filters": {
"supported_mobile_money_providers": ["vod"]
}
}

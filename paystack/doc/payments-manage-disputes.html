通过我们的API自动化处理和响应争议的过程

使用争议API时，你需要：

  1. 检索所有未决争议。这些是已向你提出但尚未得到处理的争议。
  2. 检索可用于应对争议的适用收据和其他文件。
  3. 上传争议的所有相关收据和文件
  4. 使用适用的解决方案解决争议

有关所有接口和参数的列表，请参阅 争议API 接口。

开始之前

在开始争议 API 集成之前，请确保你：

  1. 了解纠纷的处理流程。
  2. 了解 Paystack 自动代表你处理争议的情况。
  3. 在你的服务端上设置收据存储库。有关可接受收据的更多信息，请参阅这里。
  4. 了解我们遇到的争议类型。
  5. 拥有 秘密API密钥 的副本，因为它将用于 API 调用接口。

了解争议流程

当持卡人联系发卡银行并要求退还资金时，就会发生争议。争议是卡网络的一项功能，旨在保护持卡人免受欺诈活动的侵害。

争议可能因多种原因引起，包括：

  1. 与描述不符，持卡人声称从未收到货物（已借记但没有价值），或者货物与他们的期望有重大差异。
  2. 如果持卡人不记得银行对账单中的费用与什么相关，则不予认可。
  3. 欺诈，持卡人声称他们未授权购买（例如他们的卡信息被盗并被欺诈使用）。
  4. 管理错误，例如重复计费、计费金额不正确或承诺退款但从未收到。

Paystack auto 代表你处理争议的场景

All disputes raised against your integration/business should be handled within 16 hours (please 看这篇文章 for more information)

如果超过此时间，我们将自动代表你接受这些退款，并从你的 Paystack 余额中触发向受影响客户的退款。

在你的服务端上设置收据存储库

在你的应用后端，你可以有一个包含内部生成的收据的文件夹（最好采用 .pdf 格式）。我们建议，这些收据可以在收到 charge.success Webhook 通知时生成，也可以在使用 GET /transaction/{reference} 校验交易是否成功时生成。

这些收据应该（理想情况下）以交易参考作为文件名保存。例如，如果你有一个引用为 my-demo-transaction-xxx 的交易，则生成的收据的文件名称将为 my-demo-transaction-xxx.pdf。稍后你将了解这如何影响自动化流程。

争议类型

争议有两种类型：

  1. 退款
  2. 欺诈索赔

当客户为产品或服务付款但没有获得该服务的价值，但他的银行账户却被你（商户）因该服务而扣款时，通常会发生退款。

当不良行为者使用客户的付款信息进行授权交易时，就会发生欺诈。欺诈是客户向银行提出争议的主要原因。

自动化争议处理流程

你可以决定创建一个后台任务以按一定时间间隔或每天的特定时间运行此任务，或者你可能只需一个按钮即可在你选择的任何时间运行此任务。

第 1 步：获取待决争议

你可以通过致电我们的 列出争议 API 接口来完成此操作。为此有 3 个主要参数：

参数描述
from开始搜索争议的日期时间。推荐格式为yyyy-MM-ddTHH:mm:ss.SSS[Z]
to结束搜索争议的日期时间。推荐格式为yyyy-MM-ddTHH:mm:ss.SSS[Z]
status争议的状态。对于此过程，状态应为awaiting-merchant-feedback

对于日期时间搜索，让开始日期为相关日期的午夜（例如 2020-01-13T00:00:00.000Z），并让结束日期为第二天午夜之前的一秒（例如 2020-01-13T23:59:59.999Z）。

第二步：上传争议证据

还记得我们建议你使用生成收据在这里的交易参考号保存收据吗？现在我们可以使用它了。

从上一步获得的争议数组中取出每个争议，我们需要争议id和交易参考。争议 ID 将用于上传收据，而交易参考将用于从存储库获取收据。

你需要生成一个 URL 用于上传收据。你可以通过致电我们的 获取上传 URL API 接口来完成此操作。

这将返回可以上传收据的signedUrl，以及解决争议时用于识别上传的filename。

请注意，signedUrl的有效期仅为30分钟。

获得此URL后，你可以上传相应的收据作为证据，证明客户已获得所提出争议的费用的价值。

可接受的文档格式为 .jpg (image/jpg)、.jpeg (image/jpeg) 和 .pdf (application/pdf)。

要上传收据，请使用 signedUrl 发出 PUT 请求，如下面的示例代码所示。

var request = require("request");
var fs = require("fs");

fs.readFile('./transaction_reference.pdf', function (err, data) {
var options = {
method: "PUT",
url: signedUrl,
'Content-Type': 'application/pdf',
body: data
}

request(options, function (error, response, body) {
if (error) throw new Error(error);
console.log(body);
console.log("Status code: ", response.statusCode);
});
});

如果上传成功，响应中将会有一个空字符串，因此最好看到返回的状态码。

你还需要提供有关向客户提供的产品或服务的证据，因为在调查索赔时将使用这些证据。为此，你将调用我们的 添加证据API 接口。

第 3 步：解决争议

你可以在此处回应争议，接受或拒绝争议。要接受争议，你发送解决值 merchant-accepted，而要拒绝，你发送解决值 declined。如果接受争议，你可以设置要向客户退款的金额（全部或部分）。要拒绝争议，请求中将需要上传的文件名（在上一步中完成）。

你可以拨打我们的解决争议API接口解决纠纷。请注意以下事项：

  1. uploaded_filename 属性与我们为交易收据创建上传 URL 时获得的值相同。
  2. evidence属性是我们在上一步创建证据时获得的id。如果争议不是欺诈索赔，你可以将其保留为空字符串。
  3. amount 应位于 支持的货币 的子单元中。

手柄 Webhook

当你的企业记录争议时，Paystack 会发送 charge.dispute.create 事件。对于未解决的退款，我们还将每隔 4小时 发送一个 charge.dispute.remind 事件。一旦争议解决，就会发送charge.dispute.resolve事件。了解更多关于Webhook的信息。

将流程集成到你的工作流程中，确保你可以安全高效地汇款

在向客户汇款之前，你应该制定流程以确保拥有强大的集成。这些流程确保资金可以安全、轻松地发送。

余额管理

你只能发送你拥有的内容。我们在创建转账请求之前会进行余额检查。如果你没有足够的资金（包括费用），转账请求将失败，并显示Your balance is not enough to fulfill this request消息。你可以设置一个自动化程序，在发起转账请求之前获取你的 Paystack 余额。要获取 Paystack 余额，请向 检查余额API接口发出 GET 请求：

#!/bin/sh
curl https://api.paystack.co/balance
-H "Authorization: Bearer YOUR_SECRET_KEY"
-X GET
{
  "status": true,
  "message": "Balances retrieved",
  "data": [
    {
      "currency": "NGN",
      "balance": 2910971757
    }
  ]
}

响应对象中的data参数是一个对象数组。这是因为你的集成中可以有多种货币。

数据数组中的每个 balance 参数都是货币的子单位。根据你管理积分金额的方式，你可以将 balance 除以 100 或直接与子单元中已有的转账金额进行比较。

服务端审批

OTP 批准不允许你构建完全自动化的系统。但是，这不应妨碍你确认转移请求的真实性。这就是服务端批准的用武之地。它允许你创建一个 URL 来检查传输请求是否由你发起。这是一个两步过程：

  1. 创建批准URL
  2. 将 URL 添加到仪表板

创建批准URL

批准URL是POST接口，用于检查转账详细信息的真实性。如果转账详细信息是真实的，它应该响应 200，否则响应 400：

响应码含义状态
200转让已获批准pending
400转账被拒绝rejected

如果商户服务端在几秒钟内没有响应，我们将转账标记为blocked并停止进一步处理。

你应该确保你的批准URL不会运行很长的流程。这可能会导致响应时间延迟，从而导致传输被阻止。

function validateTransferRequest(request) {

}

app.post('/approval', (req, res) => {
const { body } = req
const isValidTransferRequest = validateTransferRequest(body)

if (!isValidTransferRequest) {
return res.status(400).json({})
}

return res.status(200).json({})
})

当我们发送批准请求时，我们添加用于发起传输请求的有效负载。校验请求时，你的校验逻辑应确认有效负载中的传输 参考 和 金额 与你系统上的内容匹配。

将 URL 添加到仪表板

当你完成批准URL的实施后，你需要将URL添加到PaystackDashboard。为此，请转到 Paystack Dashboard，然后导航至“设置”，然后导航至“首选项” 找到“转账审批”部分：

![图片 1：添加批准的仪表板部分的图片URL](https://paystack.com/docs/static/027c9666ffe75694210bab674a8b4eb2/c65fa/transfer-approval.png)

不要忘记点击 保存更改 按钮来完成设置过程。

在转移批准部分中，选中你要激活批准的域的复选框，然后为该域添加 URL。拒绝请求时可以执行以下两种操作：

  1. 黑名单收件人：将收款人列入黑名单后，你将无法再向收款人汇款。你可以通过 Dashboard 通过 导航至收件人页面 撤消此操作，单击收件人并切换开关。
  2. 什么也不做：我们只是不会继续处理该请求。

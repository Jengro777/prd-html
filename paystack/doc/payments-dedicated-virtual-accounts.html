了解如何为你的客户创建虚拟账户来向你付款。

此功能仅适用于在尼日利亚和加纳成功完成上线流程的注册企业。

简介

专属虚拟账户 (DVA) 是 Paystack Dashboard 和 API 上的一项功能，可让你为客户创建银行账户。这些账户允许你的客户在你的业务上进行不同的交易。

当你为客户创建专属虚拟账户 (DVA) 时，到该账户的所有银行转账都将自动记录为该客户的交易。

创建 DVA 并将其分配给客户涉及三个步骤：

  1. 创建客户
  2. 校验客户（某些业务类别需要）
  3. 为客户创建DVA

基于上述步骤，有两种可能的集成流程：

  1. 多步骤账户分配：在此流程中，你将为每个步骤发出请求并处理响应，然后再继续下一步。
  2. 单步账户分配：在此流程中，你将必要的数据传递给接口，它将处理 DVA 的创建和分配给客户。

两个流程都涉及异步进程，因此你需要设置 Webhook 来获取请求的更新。

设置Webhook

首先，你需要监听 charge.success 事件。银行转账是通过外部渠道进行的，我们只有在转账完成后才会收到通知。了解付款何时完成的唯一方法是通过 Webhook。

charge.success Webhook 事件可让你知道何时收到银行转帐付款。以下是 charge.success 事件中专属虚拟账户支付的授权对象示例：

多步骤账户分配

这适合想要控制账户创建和分配给客户的每个步骤的商户。在此流程中，你将管理客户的创建、客户的校验以及 DVA 的创建。

创建客户

专属虚拟账户与客户绑定，因此你需要通过将 email、first_name、last_name 和 phone 传递给 创建客户API 来创建客户。

如果你的平台上已存在客户，请确保设置客户的 first_name、last_name 和 phone。这是因为我们需要客户的详细信息来创建银行账户。对于没有这些详细信息创建的客户，你可以在使用 创建专属虚拟账户API 创建虚拟账户时通过传递 first_name、last_name 和 phone 来更新客户记录

单步账户分配

在此流程中，你将客户详细信息传递给我们，我们负责创建 DVA 并将其分配给客户。你的请求参数取决于你的业务类别。出于合规性原因，某些企业需要校验其客户。

所需合规性

这仅适用于尼日利亚企业。

在业务类别 -投注、金融服务 和一般服务 下提供服务的企业需要先校验客户的个人身份信息，然后才能生成银行账户。

此类别的商户需要添加客户的银行详细信息以进行校验：

curl https://api.paystack.co/dedicated_account/assign
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"email": "janedoe@test.com",
"first_name": "Jane",
"middle_name": "Karen",
"last_name": "Doe",
"phone": "+2348100000000",
"preferred_bank": "test-bank",
"country": "NG",
"account_number": "0123456789",
"bvn": "20012345678",
"bank_code": "007"
}'
-X POST
{
  "status": true,
  "message": "Assign dedicated account in progress"
}

由于客户校验步骤，你将收到两个 Webhook 事件。如果客户校验步骤失败，我们将向你发送 customeridentification.failed 和 assigndedicatedaccount.failed 事件。如果一切顺利，我们将向你发送 customeridentification.success 和 assigndedicatedaccount.success 事件。检查 处理事件 部分以了解这些事件的结构。

可选合规性

对于此类商户，你只需传递客户数据和首选银行：

curl https://api.paystack.co/dedicated_account/assign
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"email": "janedoe@test.com",
"first_name": "Jane",
"middle_name": "Karen",
"last_name": "Doe",
"phone": "+2348100000000",
"preferred_bank": "test-bank",
"country": "NG"
}'
-X POST
{
  "status": true,
  "message": "Assign dedicated account in progress"
}

dedicatedaccount.assign.success 事件在成功创建和分配DVA 时发送，而dedicatedaccount.assign.failed 事件在无法创建账户时发送。你应该查看 处理事件 部分以了解这些事件的结构。

处理事件

我们为 DVA 创建和分配的不同阶段发送以下事件：

活动描述
customeridentification.success当客户的身份得到校验时发送此信息
customeridentification.failed当无法校验客户身份时发送此信息
dedicatedaccount.assign.success当 DVA 成功创建并分配给客户时发送
dedicatedaccount.assign.failed当无法创建 DVA 并将其分配给客户时发送此消息

重新查询客户专属虚拟账户

当客户向专属虚拟账户进行转账时，系统会自动为客户创建一笔交易，并将 Webhook 发送到你的服务端以通知你该交易。这通常会在几分钟内发生。

In some cases, the notification could take longer to come in. When this happens, the customer might reach out to you that their account/wallet hasn't been credited, or they would try to refresh their balance in your app.

在这种情况下，你可以使用 重新查询专属虚拟账户API 接口检查虚拟账户中是否有尚未处理的新交易。调用此接口将触发后台重新查询过程，如果发现任何待处理的交易，则会创建该交易，并将Webhook通知发送到你的服务端。

curl https://api.paystack.co/dedicated_account/requery?account_number={accountNumber}&provider_slug={provider_slug}&date={yyyy-mm-dd}
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-X GET
{
  "status": true,
  "message": "We are checking the status of your transfer. We will send you a notification once it is confirmed"
}

你只能每十分钟重新查询一次专属虚拟账户。如果你尝试在 10 分钟内多次重新查询专属虚拟账户，则该请求将不会被处理。

专属虚拟账户分摊付款

专属虚拟账户的拆分付款允许你将收到的资金自动拆分到你的主结算银行账户和一个或多个银行账户之间的专属虚拟账户中。

有两种方法可以在专属虚拟账户上添加分期付款：

  1. 创建专属虚拟账户时添加子账户
  2. 将子账户添加到现有专属虚拟账户

对于专属虚拟账户的多次分割付款：

  1. 创建专属虚拟账户时添加分割代码
  2. 将分割代码添加到现有的专属虚拟账户

入境转账审批

仅 Paystack-Titan 虚拟账户支持此功能。

入站转账批准允许企业接受或拒绝个人交易至Paystack-Titan 虚拟账户。此功能适用于专属虚拟账户和转账付款。它使企业能够控制他们希望接收的虚拟账户交易，从而减少与管理不需要的交易和处理退款相关的管理费用。

要启用此功能，请转到“设置”页面，然后在仪表板上的首选项选项卡中查找虚拟账户。选择 Inbound Transfer Approval 选项并提供将处理 Webhook 事件的 Webhook url。

![图 1：仪表板中的转移批准图像](https://paystack.com/docs/static/3a9ffe4e914d266b2b661a5b0637ffd6/1134b/virtual_accounts_approval.png)

当客户尝试转账到账户时，Paystack 将发送一个 Webhook 事件，其中包含付款人账户和接收人账户的详细信息。你可以使用这些详细信息来做出决定。

{
  "payer_account_number": "44940573849",

  "payer_bank_code": "00711",
  "payer_bank_name": "Guaranty Trust Bank",

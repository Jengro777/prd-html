使用 Paystack，你的 Android 应用程序中的 受理支付 比以往任何时候都更容易！通过我们的Android SDK，你可以轻松开始接受客户的付款。集成过程分为两步：

在本教程中，我们将构建一个简单的食品订购应用程序，展示如何使用 Paystack Android SDK 在 Android 应用程序中受理支付。该应用程序由两个活动组成，如下所示：

![图片 1：主要活动包含芝士汉堡的图片及其描述](https://paystack.com/docs/static/5fb0ef949b6407784de12448834303d4/302a4/food_ordering_screen_1.png)![图片 2：Checkout 包含收集卡片详细信息的表单的活动](https://paystack.com/docs/static/287eb2c73d73d1d2de001d8975e2361e/302a4/food_ordering_screen_2.png)

我从 Pexels 上抓了汉堡的照片。你可以获取它 这里 或使用你喜欢吃的饭菜的图片。为了保持应用程序的尺寸精简，我选择使用较小版本的图像。

本指南假设你了解 Android开发 的基础知识。本指南的目的是向你展示如何通过 Paystack 将支付集成到你的 Android 应用程序中。

项目设置

本指南是使用 Android Studio 2023.2.1、Android Gradle plugin 7.4.2 和 Gradle 7.5 编写的。早期版本的行为可能有所不同，但最终结果应该是相同的。你还应该确保有稳定的互联网连接来安装项目依赖项。应用程序代码位于 Java 和 Kotlin 中。

如果你只对集成 SDK 感兴趣，你可以跳到 初始化付款 部分。

创建订餐应用程序

让我们打开 Android Studio 并使用以下参数创建一个新项目：

属性价值
项目模板空活动
应用程序名称食物Checkout
套餐名称com.yourdomain.appname
语言Java 或 Kotlin
最小值SDKAPI 21：Android 5.0（棒棒糖）

点击Finish按钮确认项目配置并等待项目依赖安装完成。我们将在应用程序中使用一些资源，因此最好在继续应用程序的其他部分之前设置它们。

添加汉堡图像

如果你尚未下载汉堡图片，你应该导航至 像素 并下载。我使用 Free Download 下拉菜单为图像选择自定义尺寸 (320 x 480)。当图像下载成功后，将其重命名为 burger.jpg 并拖动到应用程序的可绘制文件夹中：

![图片 3：Android Studio 的屏幕截图，其中包含更新的汉堡图像可绘制](https://paystack.com/docs/static/d29d841d4be0a60b9d27e8442cef8ca3/9f82e/as_burger_asset.png)

更新颜色文件

Android Studio 为我们创建的默认颜色与我们应用程序的设计不匹配。打开values文件夹中的colors.xml文件并使用以下代码更新它：

<?xml version="1.0" encoding="utf-8"?>
<resources xmlns:tools="http://schemas.android.com/tools">
<color name="white">#FFFFFFFF</color>
<color name="silver_400">#CBC9C9</color>
<color name="azac_500">#DEB334</color>
<color name="cod_gray_900">#171516</color>
// this is used to modify the default border color of a text input
<color name="mtrl_textinput_default_box_stroke_color" tools:override="true">#CBC9C9</color>
</resources>

更新应用程序的主题

由于我们更新了 color.xml 文件，我们的 theme.xml 将出现一些错误，因为我们删除了它之前使用的颜色参考。在更新主题之前，我们应该删除主题的夜间版本，因为我们不会使用它。然后我们可以更新我们的 theme.xml 文件，如下所示：

<resources xmlns:tools="http://schemas.android.com/tools">

<style name="Theme.FoodCheckout" parent="Theme.MaterialComponents.DayNight.NoActionBar">

<item name="colorPrimary">@color/cod_gray_900</item>

<item name="colorPrimaryVariant">#191919</item>
<item name="colorOnPrimary">@color/white</item>

<item name="colorSecondary">@color/azac_500</item>
<item name="colorSecondaryVariant">@color/azac_500</item>
<item name="colorOnSecondary">@color/cod_gray_900</item>

<item name="android:statusBarColor" tools:targetApi="l">?attr/colorPrimaryVariant</item>
</style>
</resources>

初始化付款

使用SDK，你需要在服务端上开始交易并在SDK上完成交易。要初始化交易，请在服务端上向 初始化交易API 接口发出 POST 请求：

curl https://api.paystack.co/transaction/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com",
"amount": "500000"
}'
-X POST
{
  "status": true,
  "message": "Authorization URL created",
  "data": {
    "authorization_url": "https://checkout.paystack.com/nkdks46nymizns7",
    "access_code": "nkdks46nymizns7",
    "reference": "nms6uvr1pl"
  }
}

交易成功初始化后，你会收到包含 access_code 的响应。你需要将此access_code返回到你的移动应用程序。

不要直接在你的移动应用程序上向初始化交易接口发出 API 请求，因为它需要你的密钥。你的密钥只能在可以采取更强安全措施的服务端上使用。

access_code就位后，你现在可以使用SDK来完成交易。

安装SDK

Android SDK 提供受理支付的方法和接口。要使用 SDK，请将 paystack-ui 添加到应用程序的 build.gradle 文件中：

安装前你应该检查梅文中心以获取最新版本。

  • 构建.gradle
dependencies {
implementation 'com.paystack.android:paystack-ui:0.0.9'
}

由于我们对 build.gradle 文件进行了一些更改，因此我们需要同步项目以安装所需的依赖项。

集成 Paystack SDK

我们现在将充实 MainActivity 来处理先前发起的付款的完成。这是一个 3 步过程：

  1. 初始化SDK
  2. 实施回调
  3. 创建付款表

初始化SDK

在加载 UI 之前，SDK 使用构建器模式来处理基础配置。你可以在此处添加公钥，如下所示：

Paystack.builder()
.setPublicKey("pk_domain_xxxxxxxx")
.setLoggingEnabled(true)
.build()

实现一个回调

根据用户的操作或处理器的响应，交易可以处于不同的状态。为了正确协调交易，你需要设置一个回调：

private fun paymentComplete(paymentSheetResult: PaymentSheetResult) {
val message = when (paymentSheetResult) {
PaymentSheetResult.Cancelled -> "Cancelled"
is PaymentSheetResult.Failed -> {
Log.e("Something went wrong", paymentSheetResult.error.message.orEmpty(), paymentSheetResult.error)
paymentSheetResult.error.message ?: "Failed"
}

is PaymentSheetResult.Completed -> {

Log.d("Payment successful", paymentSheetResult.paymentCompletionDetails.toString())
"Successful"
}
}

Toast.makeText(this, "Payment $message", Toast.LENGTH_SHORT).show()
}

创建付款表

在应用程序的活动中启动界面需要 PaymentSheet。它需要两个参数，将在其中呈现的活动以及交易完成时调用的回调函数：

private lateinit var paymentSheet: PaymentSheet

override fun onCreate(savedInstanceState: Bundle?) {
super.onCreate(savedInstanceState)
setContentView(R.layout.activity_main)



paymentSheet = PaymentSheet(this, ::paymentComplete)


}

PaymentSheet 附带一个 launch 方法，允许你触发组件的显示。 launch 方法从先前初始化的交易中获取 access_code。

fun makePayment() {

paymentSheet.launch("br6cgmvflhn3qtd")
}

可以在按钮的点击监听中添加makePayment方法来触发PaymentSheetUI。

测试集成

我们现在可以测试我们的应用程序以确保它按预期工作。我们有几个 测试卡 可用于模拟不同的支付场景。

确认付款

在向客户提供服务之前，你应始终确认付款。

本部分假设你有一个移动应用程序所依赖的后端服务端。你需要使用 Webhook URL 监听事件。

Webhook 允许 Paystack 向你实时发送集成中发生的事件。付款成功后，我们将向你的 Webhook URL 发送 charge.success 事件，其中包含有关成功交易的信息。建议你监听此事件以确认付款。当客户出现连接问题以及支付处理商出现延迟时，这种交易确认方法更具弹性。

或者，你可以将交易参考从应用程序发送到后端服务端。然后，从你的服务端，你可以使用交易参考调用我们的 校验交易API 接口。响应正文将包含一个状态字段，指示交易是否成功。

定期付款

当交易被确认时，响应正文将包含一个 authorization 对象：

{
...
"data": {
...
"authorization": {
"authorization_code":"AUTH_8dfhjjdt",
"card_type":"visa",
"last4":"1381",
"exp_month":"08",
"exp_year":"2018",
"bin":"412345",
"bank":"TEST BANK",
"channel":"card",
"signature": "SIG_idyuhgd87dUYSHO92D",
"reusable":true,
"country_code":"NG"
},
...
}
}

当authorization具有"reusable": true值时，客户的卡可用于定期付款。你可以存储authorization_code并用于后续付款。

通过 Paystack 批量转账 API 一次向多个收款人汇款

某些商业模式需要同时向多个客户汇款。例如，工资管理系统要求在每月的某个时间向所有员工发送工资。诸如此类的大笔支出需要仔细协调，以确保所有客户都能获得报酬，并且你的系统不会不堪重负。

批量传输API 接口处理大量支出编排，帮助企业专注于为客户提供价值。

要在 Paystack 上汇款，你需要 API 密钥来校验你的转账。你可以在 Paystack Dashboard 的设置 → API 密钥和 Webhook 下找到你的密钥。

创建收件人

转账收款人是你的积分受益人，你可以向其汇款。在向客户汇款之前，你需要先收集他们的详细信息，然后使用他们的详细信息创建转账收件人。我们支持不同国家的不同接收者：

类型描述货币
ghipss这意味着加纳银行间支付和结算系统。它代表加纳的银行账户。GHS
mobile_moneyMobile Money 或 MoMo 是与手机号码绑定的账户。GHS/KES
kepss这是肯尼亚电子支付和结算系统。它代表肯尼亚的银行账户。KES
nuban这意味着尼日利亚统一银行帐号。它代表尼日利亚的银行账户。NGN
basa这指的是南非银行业协会。它代表南非的银行账户。ZAR
authorization这是代表客户卡的唯一代码。用户使用卡付款后，我们会返回授权码。全部

创建后，将 recipient_code 保存到你的 DB 并使其可用于传输启动。这是传输生命周期中的一次性过程。由于你会定期向多个收件人汇款，因此你只需针对每个转账请求从 DB 获取收件人。

管理批次

在创建转账请求之前，你需要将请求分成批次。批次是请求的子集，可以更轻松地管理和跟踪传输。在代码中，批次是传输对象的数组：

{
  "transfers": [
    {
      "amount": 20000,
      "reference": "acv_2627bbfe-1a2a-4a1a-8d0e-9d2ee6c31496",
      "reason": "Bonus for the week",
      "recipient": "RCP_gd9vgag7n5lr5ix"
    },
    {
      "amount": 35000,
      "reference": "acv_1bd0c1f8-78c2-463b-8bd4-ed9eeb36be50",
      "reason": "Bonus for the week",
      "recipient": "RCP_zpk2tgagu6lgb4g"
    },
    {
      "amount": 15000,
      "reference": "acv_11bebfc3-18b3-40aa-a4df-c55068c93457",
      "reason": "Bonus for the week",
      "recipient": "RCP_dfznnod8rwxlwgn"
    }
  ]
}

你应该始终为每个传输对象生成唯一的传输引用。转账参考将帮助你跟踪和管理每次转账。你可以查看 生成传输参考 部分以了解更多信息。

transfers数组中的每个对象对于单个请求来说都是相同的参数。一个批次不应包含超过 100 件，并且每个批次应每隔 5秒 发送：

参数配置
批量大小<= 100
持续时间每 5 秒一次

通过URL设置转账审批的商户应确保他们可以在几秒（最好是微秒）内批准每批中的所有转账，否则他们可能会面临blocked状态的转账。因此，在规划批量大小时，你应该考虑校验每次传输的真实性所需的时间。

持续时间是为了避免受到速率限制。短时间间隔发送多个请求会导致 429（请求过多）错误。

正确规划和实施批次后，你现在可以启动批量传输。

启动批量传输

如果你已启用OTP进行转账审批，则需要禁用它才能使用此接口。

除了批次中的transfers数组之外，你还需要添加currency和source以向批量传输API接口发出请求：

#!/bin/sh
url="https://api.paystack.co/transfer/bulk"
authorization="Authorization: Bearer YOUR_SECRET_KEY"
content_type="Content-Type: application/json"
data='{
"currency": "NGN",
"source": "balance",
"transfers": [
{
"amount": 20000,
"reference": "acv_2627bbfe-1a2a-4a1a-8d0e-9d2ee6c31496",
"reason": "Bonus for the week",
"recipient": "RCP_gd9vgag7n5lr5ix"
},
{
"amount": 35000,
"reference": "acv_1bd0c1f8-78c2-463b-8bd4-ed9eeb36be50",
"reason": "Bonus for the week",
"recipient": "RCP_zpk2tgagu6lgb4g"
},
{

与单次传输不同，响应对象中的 data 参数返回一个对象数组。每个对象代表批次中的一次传输。需要注意的是，传输状态的工作方式与单次传输类似。如果你需要回顾如何更新传输状态，你可以查看传输生命周期。

测试传输始终返回success，因为不涉及任何处理。实时传输在处理时会排队，因此你需要设置 Webhook URL 来接收你请求的更新。

虽然你可能已批量发送转账，但系统会针对批量中的每笔转账发送通知。因此，如果你的批次中有 100 笔转账，你将收到该批次的 100 个事件（每次转账一个）。

校验转账

由于排队和处理时间的原因，传输的更新并不总是即时的，因此你需要设置一个 Webhook URL，我们将在处理完成时进行 POST 更新。

通过Webhook校验

url="https://api.paystack.co/transfer/verify/{reference}"

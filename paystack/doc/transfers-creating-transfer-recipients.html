要通过集成汇款，你需要收集客户的详细信息以创建受益人。

转账收款人是在你的集成中创建的受益人，允许你汇款。在通过集成汇款之前，你需要收集客户的详细信息并使用他们的详细信息创建转账收件人。

我们支持以下收件人类型：

类型描述货币
ghipss这意味着加纳银行间支付和结算系统。它代表加纳的银行账户。GHS
mobile_moneyMobile Money 或 MoMo 是与手机号码绑定的账户。GHS/KES
kepss这是肯尼亚电子支付和结算系统。它代表肯尼亚的KES和USD银行账户。KES/USD
nuban这意味着尼日利亚统一银行帐号。它代表尼日利亚的银行账户。NGN
basa这指的是南非银行业协会。它代表南非的银行账户。ZAR
authorization这是代表客户卡的唯一代码。用户使用卡付款后，我们会返回授权码。全部

要创建转账收件人，请向 转账接收者API 发出 POST 请求，并传递以下客户详细信息之一：

  1. 银行账户
  2. 移动货币
  3. 授权码

银行账户

创建具有银行账户的转账收件人时，你需要收集客户的银行详细信息。通常，帐号和关联银行就足够了，但有些国家/地区需要更多详细信息，特别是用于账户校验。你应该设计你的界面，以允许收集运营所在国家/地区的必要详细信息。

列出银行

创建界面 (UI) 来收集用户的银行详细信息时，你需要使用银行列表填充 UI。我们提供了 列出银行API 接口，你可以使用它在你所在国家/地区的可用银行中填充你的 UI。

要获取某个国家/地区的银行列表，请发出 GET 请求，并在查询参数中传递 currency：

curl https://api.paystack.co/bank?currency=NGN
-H "Authorization: Bearer YOUR_SECRET_KEY"
-X GET

校验帐号

你需要收集目的地账号并确认其有效。这是为了确保你不会将资金发送到错误或无效的账户。

如前所述，账户校验在不同国家/地区需要不同的详细信息。你可以按照下表中的操作所在国家/地区的账户校验流程进行操作：

货币校验
NGN/GHS解析帐号
ZAR校验账户

创建收件人

校验完成后，你可以将客户的银行详细信息和收款人type传递给创建转账收件人 API接口：

curl https://api.paystack.co/transferrecipient
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "type": "nuban",
"name": "John Doe",
"account_number": "0001234567",
"bank_code": "058",
"currency": "NGN"
}'
-X POST

移动货币

此功能目前可供加纳和肯尼亚的企业使用。

curl https://api.paystack.co/bank?currency=GHS&type=mobile_money

肯尼亚企业有多种针对 bank_code 的移动货币选择：

  1. MPESA 对于个人 Mpesa 用户
  2. MPPAYBILL 用于付款单编号，并在付款期间需要其他信息
  3. MPTILL 商业 Till 号码

Paybill 和 Till 号码的收件人类型为 mobile_money_business。

客户刷银行银行卡支付成功后返回授权码。结合授权码和用于付款的邮箱地址，你可以创建转账收件人：

curl https://api.paystack.co/transferrecipient
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "type": "authorization",
"name": "Revs Ore",
"email": "revs@ore.com",
"authorization_code": "AUTH_ncx8hews93"
}'
-X POST

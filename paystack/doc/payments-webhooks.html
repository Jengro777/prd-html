API 变更日志

Webhook 允许你设置一个通知系统，该系统可用于接收对 Paystack API 发出的某些请求的更新。

简介

通常，当你向 API 接口发出请求时，你希望得到近乎立即的响应。但是，某些请求可能需要很长时间才能处理，这可能会导致超时错误。为了防止超时错误，将返回待处理的响应。由于你的记录需要根据请求的最终状态进行更新，因此你需要：

  1. 提出更新请求（通常称为轮询）或者，
  2. 使用 Webhook URL 监听事件。

我们建议你使用 Webhook 为你的客户提供价值，而不是使用回调或轮询。使用回调，我们无法控制客户端发生的情况。你也没有。如果客户设备上的网络连接失败或较弱，或者设备在交易后关闭，则回调可能会失败。

轮询 vs Webhook

![图 1：显示轮询和 Webhook 之间的比较的图像](https://paystack.com/docs/static/4e48ac469a56d3f950460a6f7203b0fe/4352a/polling_Webhook.png)

轮询需要定期发出 GET 请求来获取请求的最终状态。例如，当客户进行交易付款时，你不断请求交易状态，直到获得成功的交易状态。

使用 Webhook，资源服务端（本例中为 Paystack）会在请求状态发生变化时向你的服务端发送更新。请求状态的变化称为 事件。你通常会在称为 Webhook URL 的 POST 接口上监听这些事件。

创建一个 Webhook URL

Webhook URL 只是资源服务端向其发送更新的POST 接口。 URL需要解析JSON请求并返回200 OK：

app.post("/my/webhook/url", function(req, res) {

const event = req.body;

res.send(200);
});

当你的 Webhook URL 接收到事件时，它需要解析并确认该事件。确认事件意味着在 HTTP 标头中返回 200 OK。如果响应标头中没有 200 OK，则会在接下来的 72 小时内发送事件：

  • 在生产模式下，前 4 次尝试每 3 分钟发送一次 Webhook 事件，然后在接下来的 72 小时内每小时重试一次
  • 在测试模式下，Webhook 事件每小时发送一次，持续 10 小时，请求超时为 30 秒。

如果你的 Webhook 函数中有额外的任务，你应该立即返回 200 OK 响应。长时间运行的任务会导致请求超时并从服务端发出自动错误响应。如果没有 200 OK 响应，则按照上一段所述重试。

校验事件来源

由于你的 Webhook URL 是公开可用的，因此你需要校验事件是否源自 Paystack 而不是不良参与者。有两种方法可以确保发送到你的 Webhook URL 的事件来自 Paystack：

  1. 签名校验
  2. IP 白名单

签名校验

从 Paystack 发送的事件带有 x-paystack-signature header。此标头的值是使用你的密钥签名的事件负载的HMAC SHA512签名。应在处理事件之前校验标头签名：

const crypto = require('crypto');
const secret = process.env.SECRET_KEY;

app.use(express.json({
verify: (req, res, buf) => {
req.rawBody = buf;
}
}));

app.post("/my/webhook/url", function(req, res) {

const hash = crypto.createHmac('sha512', secret).update(req.rawBody).digest('hex');
if (hash == req.headers['x-paystack-signature']) {

const event = req.body;

}
res.send(200);
});

IP 白名单

使用此方法，你只允许某些 IP 地址访问你的 Webhook URL，同时阻止其他地址。 Paystack 只会从以下 IP 地址发送 Webhook：

  1. 52.31.139.75
  2. 52.49.173.169
  3. 52.214.14.220

你应该将这些 IP 地址列入白名单，并将来自其他 IP 地址的请求视为伪造。

上面列出的IP地址适用于测试和实际环境。你可以在暂存和生产环境中将它们列入白名单。

上线清单

现在你已经成功创建了 Webhook URL，以下是一些确保你获得愉快体验的方法：

  1. 将 Webhook URL 添加到你的 Paystack 仪表板 或 画布
  2. 确保你的 Webhook URL 是公开可用的（本地主机 URL 无法接收事件）
  3. 如果使用.htaccess，请记住将尾随/添加到URL
  4. 测试你的 Webhook 以确保你获得 JSON 主体并返回 200 OK HTTP 响应
  5. 如果你的 Webhook 函数具有长时间运行的任务，则应首先通过返回 200 OK 确认接收到 Webhook，然后再继续处理长时间运行的任务
  6. 如果我们没有从你的 Webhook 收到 200 OK HTTP 回复，我们会将其标记为失败的尝试
  7. 在生产模式下，前 4 次尝试每 3 分钟重试一次失败的尝试，然后在接下来的 72 小时内每小时重试一次
  8. 在测试模式下，在接下来的 10 小时内每小时重试失败的尝试。每次尝试的超时时间为 30 秒。

查看和重新发送事件

我们记录尝试传递给你的 Webhook URL 的每个 Webhook 事件，包括其负载和你的服务端返回的响应。使用 Webhook 事件 API 可以：

  • 按类别、事件类型、状态或日期列出和过滤你的事件历史记录
  • 将一组事件或与过滤器匹配的每个事件重新发送到你当前的 Webhook URL

我们将每个事件重新发送到为你进行身份校验的环境配置的 Webhook URL。

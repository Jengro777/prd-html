你可以通过在销售点系统、网络或移动应用程序上发起付款请求并在 Paystack 终端上完成来接受当面付款

简介

Paystack 终端可帮助你弥合线上和线下支付之间的差距。你可以从为你的销售点系统、网络或移动应用程序提供支持的服务端创建付款请求，并使用我们的终端离线完成支付。

集成流程分为三步：

  1. 创建付款请求
  2. 将付款请求发送至终端
  3. 收听付款通知

![图 1：推送事件集成流程图](https://paystack.com/docs/static/3480532ec2d6ea28a7afbd63645b33b4/6029f/instant-payment.png)

创建付款请求

本文档重点介绍如何将付款发送到我们的终端。你可以参考如何创建发票进一步了解付款请求

当用户选择了商品并准备付款时，你可以从应用程序向我们的 /paymentrequest 接口发起付款请求：

curl https://api.paystack.co/paymentrequest
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"customer": "CUS_5lgv9bc41uw15pb",
"description": "Invoice for Damilola",
"line_items": [
{ "name": "Pancakes and sausage", "amount": "2000", "quantity": 1 },
{ "name": "Chicken Salad", "amount": "3000", "quantity": 1 }
]
}'
-X POST

检查终端状态

或者，在将付款请求推送到终端之前，你可能需要检查终端是否在线并且可以接收请求。你可以向终端状态API发出请求来检查终端的状态：

curl https://api.paystack.co/terminal/:id/presence
-H "Authorization: Bearer YOUR_SECRET_KEY"
-X GET

{
  "status": true,
  "message": "Terminal status retrieved",
  "data": {
    "online": true,
    "available": true
  }
}

如果同时满足online: true和available: true，则终端已准备好接收请求。如果任一参数为 false，请确保终端未用于处理付款。

推送到终端

Paystack Terminal可以接收并处理从商户服务端发送的支付请求，从而使开发人员能够构建令人愉快的亲身体验。

为了在终端上完成支付请求，你需要向终端事件 API发出请求，并传递先前创建的支付请求的id和offline_reference：

curl https://api.paystack.co/terminal/:terminal_id/event
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"type": "invoice",
"action": "process",
"data": {
"id": 7895939,
"reference": 4634337895939
}
}'
-X POST
{
  "status": true,
  "message": "Event sent to Terminal",
  "data": {
    "id": "616d721e8c5cd40a0cdd54a6"
  }
}

校验事件传递

当你向终端推送时，如果响应成功，则表明我们的服务端已成功接收推送请求并转发至终端。这并不一定意味着设备已成功接收请求。

要确认终端收到事件，可以向终端事件状态 API发出请求：

curl https://api.paystack.co/terminal/:terminal_id/event/:event_id
-H "Authorization: Bearer YOUR_SECRET_KEY"
-X GET
{
  "status": true,
  "message": "Message Status Retrieved",
  "data": {
    "delivered": true
  }
}

终端收到支付请求后，会显示支付请求详情，供客户查看并进行支付。

你只能确认设备在请求发起后 48 小时内收到了事件

收听通知

支付发票费用后，我们会使用 Webhook 向你的服务端发送更新。在你的 Webhook URL 上，你应该监听这些事件：

活动描述
charge.success当客户成功付款时发送此信息。它包含交易、客户和卡详细信息。
paymentrequest.success发送此信息也表明发票付款成功。它包含发票详细信息。
paymentrequest.pending当付款请求成功创建时发送。
invoice.payment_failed当发票付款失败时发送此信息。

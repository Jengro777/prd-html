你可以创建发票，用于在订单履行时在 Paystack 终端上受理支付

简介

某些商业模式允许客户下订单购买商品和服务，并可以选择在订单履行时付款。这通常称为货到付款或货到付款。由于订单履行时间可能从几分钟到几个月不等，商户将在未来收到付款。

未来接收付款的主要问题之一是通常必须手动对账。除了繁琐的手动对账过程之外，商户无法获得付款的实时更新。

通过我们的付款请求 API，你可以创建可在任何 Paystack 终端上获取和付款的发票。这使你可以轻松接收付款，同时自动对账。

集成流程分为三步：

  1. 创建一个客户（如果尚不存在），使用 客户API
  2. 使用 付款请求API 创建发票
  3. 收听你的 Webhook URL 上的事件

创建客户

如果客户已存在于你的集成中，你可以获取他们的 customer_code 并继续下一部分

要接受订单履行付款，你需要向客户开具发票。因此，在创建发票之前，客户应该存在。

专门为 Paystack 终端创建客户时，客户不必是个人。它可以是你的：

要创建客户，你需要向客户API发出POST请求：

curl https://api.paystack.co/customer
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "zero@sum.com"
"first_name": "Zero",
"last_name": "Sum",
"phone": "+2348123456789"
}'
-X POST
{

  "message": "Customer created",
  "data": {
    "transactions": [],
    "subscriptions": [],

成功创建客户后，你应该将响应对象中的 customer_code 和 id 保存到数据库中。创建发票时你将需要这两个参数。

创建发票

可以使用 付款请求API 创建两种类型的发票：

  1. 简易发票
  2. 专业发票

两张发票之间的主要区别在于它们包含的详细信息。当发票加载到终端上时，它会向客户显示该发票的详细信息。你的选择取决于你的业务逻辑和用户体验。

简易发票

简单的发票包含客户订单的总金额。当你希望客户应支付的总金额具有灵活性时，这非常有用。例如，你可能正在开展买二送一活动，客户可以以一件商品的价格购买两件商品。

-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"customer": "CUS_gv2e6wdd0os1rd4",
"amount": 40000,
"description": "2-for-1 promo"

专业发票

离线参考

成功创建发票后，返回的 JSON 响应包含 offline_reference 等参数。离线参考是一个唯一的标识符，将用于将来完成支付。你应该将其保存在数据库中并将其发送给你的客户：

  • 短信，或

如果使用有效的邮箱，我们还会向客户发送发票副本。发送给客户的邮箱也有 offline_reference。

受理支付

Paystack 终端可用于通过以下方式接受发票付款：

  1. 使用离线参考作为输入
  2. 扫描代表离线参考的QR码

![图片 1：终端屏幕包含一个用于填写离线参考的输入字段](https://paystack.com/docs/static/6dae5c9024747166f77b7214e56407d3/5ff7e/find-invoice.png)![图 2：终端屏幕扫描代表离线参考的 QR 代码](https://paystack.com/docs/static/ca1f1376dcfde6beede79b10e008219e/5ff7e/scan-code.png)

无论你选择哪个选项，发票都会显示在终端上，供你的客户查看并为其商品付款。

收听通知

支付发票费用后，我们会使用 Webhook 向你的服务端发送更新。在你的 Webhook URL 上，你应该监听这些事件：

活动描述
charge.success当客户成功付款时发送此信息。它包含交易、客户和卡详细信息。
paymentrequest.success发送此信息也表明发票付款成功。它包含发票详细信息。
paymentrequest.pending当付款请求成功创建时发送。
invoice.payment_failed当发票付款失败时发送此信息。

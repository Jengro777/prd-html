API 变更日志

了解企业如何在服务交付后收取最终金额之前在卡上保留金额。

此功能仅适用于已成功完成上线流程的南非注册企业。

简介

预授权允许你在收取最终金额之前保留客户账户中的金额。这分两步发生：

  1. 初始化预授权交易
  2. 收取最终金额

在保留期内，资金仍在客户的账户中，但他们无法访问。这保证了服务交付后资金可用。提供服务后付款的企业利用这一点来最大限度地降低不付款的风险。例如，网约车服务、货到付款的电子商务服务以及在线酒店预订平台。

默认保持时间为 五 (5) 天，但是，你可以使用 expire_after_days 参数将其延长至七 (7) 天。你可以使用 expire_action 参数指定在到期日采取的操作。这可以是 capture 或 release。

![图片 1：显示预授权流程图的图片](https://paystack.com/docs/static/723256bb55ba730ffefc6ca312b867f8/4e6ec/preauth_flow.png)

通过预授权向现有客户收费仅需要两个接口：

  1. 初始化预授权：此接口启动首次客户的预授权流程。它会保留要收取的金额，但尚未处理该费用。
  1. 捕获预授权：此接口向客户收取最终金额。如果金额低于初始预授权金额，余额将自动释放给客户。

预授权需要 Webhook，因为它是异步流程。设置 Webhook 接口以接收状态更改的更新。了解更多关于设置Webhook的信息。

首次预授权

要预授权交易，你将使用 初始化预授权API 接口。这会将 URL 返回到 Paystack Checkout，客户在其中输入他们的卡详细信息。这与重定向流程类似，但是资金仍保留在客户的账户中。在你致电 捕获预授权API 接口之前，他们不会收取费用。

要初始化预授权，你需要传递email、amount和currency。

curl https://api.paystack.co/preauthorization/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com",
"amount": "500000",
"currency": "ZAR"
}'
-X POST
{
  "status": true,
  "message": "Authorization URL created",
  "data": {
    "authorization_url": "https://checkout.paystack.com/preauthorization/NDEyOTIyOmxpdmU6ZWloZ2VodTNyczZjanJj",
    "access_code": "NDEyOTIyOmxpdmU6ZWloZ2VodTNyczZjanJj",
    "reference": "eihgehu3rs6cjrc"
  }
}

下表显示了初始化预授权时可以传递的其他可选参数。

完成预授权

成功交付服务后，你需要在保留期结束前完成交易。你可以使用 捕获预授权API 接口来执行此操作。此接口需要reference、amount、currency进行充电。该金额应小于或等于初始金额。

捕获时，如果 Paystack 没有得到明确的响应，预授权将进入持续状态，并轮询处理器以获得最终响应。如果收到响应，则异步更新预授权。如果没有收到响应，则进入capture_failed状态。

-H "Content-Type: application/json"

"currency": "ZAR",
"amount": "1000"

解除预授权

如果你决定不向客户收费或他们取消了收费，你将使用 释放预授权API 接口释放资金。这个接口只需要在请求正文中传递引用。客户在提出请求后几分钟内即可获得资金。

curl https://api.paystack.co/preauthorization/release
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"reference": "123-abc"
}'
-X POST
{
  "status": true,
  "message": "Successfully released",
  "data": {
    "id": 507,
    "status": "released",
    "reference": "123-abc"
  }
}

现有客户预授权

所有可重用参数为 true 的活动卡授权均可用于预授权。你应该确保authorization_code和email与第一次交易时使用的相同，否则预授权将不会成功。这与我们的定期付款收费授权类似。

在 Paystack 上，当客户向企业付款时，我们会创建一个与该客户关联的授权对象。授权对象是卡的标记化版本。

因此，如果现有客户已经在你的 Paystack 业务上通过卡付款，你可以跳过初始化预授权步骤，直接使用 预留预授权API 接口。客户无需再次输入银行卡详细信息。

保留授权接口接受与初始化预授权接口相同的参数，只是它需要authorization_code。

-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"email" : "test@paystack.com",
"currency": "ZAR",
"amount": 1000,
"authorization_code": "AUTH_dalhwqi5vw",

-X POST

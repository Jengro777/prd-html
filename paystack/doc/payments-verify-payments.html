校验付款

简而言之

校验交易API允许你确认客户交易的状态。

交易状态

Webhook 是确认交易状态的首选选项，但我们目前仅针对成功的交易发送 Webhook 事件。但是，交易可以具有以下状态：

状态含义
abandoned客户尚未完成交易。
failedThe transaction failed. For more information on why, refer to the message/gateway response.
ongoing客户当前正在尝试执行操作来完成交易。当我们等待客户输入 OTP 或进行转账（对于转账付款交易）时，可以返回此信息。
pending目前该交易正在进行中。
processing与pending相同，但适用于直接借记交易。
queued该交易已排队等待稍后处理。仅适用于批量收费交易。
reversed交易被撤销。这可能意味着交易已退款，或者已成功记录该交易的退款。
success交易已成功处理。

校验交易

你可以通过使用交易引用从服务端向 校验交易API 接口发出 GET 请求来完成此操作。这取决于你用于初始化交易的方法。

来自 Popup 或手机 SDK

你必须将引用发送到你的服务端，然后从你的服务端调用校验接口。

来自重定向API

你从你的回调 URL 发起此请求。交易参考作为查询参数返回到你的callbackURL。

有用的提示

如果你提供数字价值，例如通话时间、钱包充值、数字信用等，请务必确认你尚未为该交易提供价值，以避免双重履行，特别是如果你还使用Webhook。

警告

API 响应有一个状态键 response.status 指示 API 调用的状态。这是不交易的状态。交易的状态位于校验API响应中的data对象中，即response.data.status。了解更多关于Paystack API 格式的信息。

响应还包括gateway_response_code。查看 网关响应 了解完整的值列表以及它们如何映射到响应代码。

向回访用户收费

verify响应还返回有关用户在data.authorization对象中支付的支付工具的信息。如果通道是card，那么你可以针对该用户存储该卡的authorization_code，并使用该费用向用户收取后续交易费用。了解更多关于经常性费用的信息。

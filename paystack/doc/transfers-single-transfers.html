使用转账API向你的客户汇款

你可以通过四个简单的步骤进行转账：

  1. 创建转账收件人
  2. 生成转移参考
  3. 发起转账
  4. 监听传输状态

要在 Paystack 上汇款，你需要 API 密钥来校验你的转账。你可以在 Paystack Dashboard 的设置 → API 密钥和 Webhook 下找到你的密钥。

创建转账收件人

转账收款人是你的积分受益人，你可以向其汇款。在向客户汇款之前，你需要先收集他们的详细信息，然后使用他们的详细信息创建转账收件人。我们支持不同国家的不同接收者：

类型描述货币
ghipss这意味着加纳银行间支付和结算系统。它代表加纳的银行账户。GHS
mobile_moneyMobile Money 或 MoMo 是与手机号码绑定的账户。GHS/KES
kepss这是肯尼亚电子支付和结算系统。它代表肯尼亚的银行账户。KES
nuban这意味着尼日利亚统一银行帐号。它代表尼日利亚的银行账户。NGN
basa这指的是南非银行业协会。它代表南非的银行账户。ZAR
authorization这是代表客户卡的唯一代码。用户使用卡付款后，我们会返回授权码。全部

数据对象中的 recipient_code 是用户的唯一标识符，将用于向该客户进行转账。此代码应与客户记录一起保存在数据库中。

生成转移参考

转移参考是一个唯一标识符，可让你跟踪、管理和协调针对集成提出的每个转移请求。转账参考可让你防止双重记入，因为你可以重试非结论性转账，而不是发起新请求。

为了利用转移参考，你需要为每个请求生成并提供它。我们建议生成 v4 UUID参考不超过50 个字符。但是，无论你决定实现什么逻辑，都需要注意以下限制：

  1. 参考文献只能包含小写字母 (a-z)、数字 (0-9) 和以下符号：下划线 (_) 和破折号 (_)
  2. 最小长度应为 16 个字符
  3. 最大长度应为 50 个字符
  4. 你可以在引用前面或后面添加特殊标识符，以进一步减少冲突的可能性
{
  "source": "balance",
  "reason": "Bonus for the week",
  "amount": 100000,
  "recipient": "RCP_gd9vgag7n5lr5ix",
  "reference": "acv_9ee55786-2323-4760-98e2-6380c9cb3f68"
}

发起转账

要向客户汇款，你可以向 启动传输API 发出 POST 请求，并传递先前创建的 reference 和 recipient_code。

在构建完全自动化的系统时，你可能需要禁用 OTP 进行传输。你可以从 Paystack Dashboard 上的 首选项选项卡 禁用OTP。你应该取消选中 发送前确认转账 复选框，如下图所示。

![图1：OTP传输禁用状态图](https://paystack.com/docs/static/fc8433d173880ec22798a363ba565ab8/098c1/disabled_otp.png)

curl https://api.paystack.co/transfer
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"source": "balance",
"amount": 100000,
"reference": "acv_9ee55786-2323-4760-98e2-6380c9cb3f68",
"recipient": "RCP_gd9vgag7n5lr5ix",

当你发送此请求时，如果没有错误，则会在处理传输时返回带有待处理状态的响应。

如果转账请求出现错误，你应该使用相同的“参考”重试交易以避免双重记入。如果使用新的reference，则传输将被视为新请求。

测试传输总是返回成功，因为不涉及任何处理。实时传输处理通常需要几秒钟到几分钟的时间。处理完成后，系统会向你的 Webhook URL 发送通知。

校验转账

启动传输后，可能需要几秒钟或几分钟的时间来处理。这就是为什么我们建议依靠 Webhook 进行校验而不是轮询。

#!/bin/sh
url="https://api.paystack.co/transfer/verify/{reference}"
authorization="Authorization: Bearer YOUR_SECRET_KEY"

curl "$url" -H "$authorization" -X GET

要受理支付，请使用我们的 API、我们的客户端 JavaScript 库、Popup JS 或我们的 SDK 创建交易。每笔交易都包含一个可用于完成支付的链接。

Paystack Popup 是一个 JavaScript 库，允许开发人员为其 Web 应用程序构建安全且方便的支付流程。你可以通过 CDN、NPM 或 Yarn 将其添加到你的前端应用程序：

<script src="https://js.paystack.co/v2/inline.js">

如果你使用 NPM 或 Yarn，请确保导入库，如下所示：

import PaystackPop from '@paystack/inline-js'

成功安装库后，你现在可以开始三步集成过程：

  1. 初始化交易
  2. 完成交易
  3. 校验交易状态

初始化交易

首先，你需要从后端初始化交易。从后端初始化交易可确保你完全控制交易细节。为此，请从后端向 初始化交易API 接口发出 POST 请求：

curl https://api.paystack.co/transaction/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com",
"amount": "500000"
}'
-X POST
{
  "status": true,
  "message": "Authorization URL created",
  "data": {
    "authorization_url": "https://checkout.paystack.com/nkdks46nymizns7",
    "access_code": "nkdks46nymizns7",
    "reference": "nms6uvr1pl"
  }
}

响应的 data 对象包含完成交易所需的 access_code 参数。你应该存储此参数并将其发送到你的前端。

切勿直接从前端调用 Paystack API，以避免在前端暴露你的密钥。对 Paystack API 的所有请求都应从你的服务端发起，并且你的前端从服务端获取响应。

完成交易

你的前端应用程序应向后端发出请求以初始化交易并获取 access_code，如上一节所述。从后端获取access_code后，你可以使用Popup来完成交易：

const popup = new PaystackPop()
popup.resumeTransaction(access_code)

resumeTransaction方法触发浏览器中的结账，允许用户选择自己喜欢的支付渠道来完成交易。你可以查看 InlineJS 参考指南 了解Popup V2 中提供的功能。

校验交易状态

最后，你需要通过使用 Webhook或校验交易接口确认交易的状态。无论使用哪种方法，你都需要使用以下参数来确认是否应该向客户交付价值：

参数描述
data.status表示支付是否成功
data.amount这表示你的产品或服务的价格（以你的货币的较低面值表示）。

在校验交易状态时，你还应该校验金额，以确保其与你提供的服务的价值相匹配。如果金额不匹配，则不会向客户提供价值。

重定向

在这里，你从服务端调用 初始化交易API 来生成结账链接，然后将用户重定向到该链接以便他们可以付款。付款后，用户将返回你的网站callback_url

确认你的服务端可以与 Paystack 服务端建立 TLSv1.2 连接。大多数最新的软件都具有此功能。如果你有任何 SSL 错误，请联系你的服务提供商以获取指导。

收集客户信息

要初始化交易，你需要传递邮箱、名字、姓氏金额、交易参考等信息。邮箱和金额为必填项。你还可以在 metadata 对象字段中传递任何其他附加信息。

如果你已经存储了客户信息，则可以从你的数据库、会话或 cookie 中检索客户信息，或者从如下例所示的表单中检索客户信息。

<form action="/save-order-and-pay" method="POST">
<input type="hidden" name="user_email" value="<?php echo $email; ?>">
<input type="hidden" name="amount" value="<?php echo $amount; ?>">
<input type="hidden" name="cartid" value="<?php echo $cartid; ?>">
<button type="submit" name="pay_now" id="pay-now" title="Pay now">Pay now</button>
</form>

初始化交易

当客户单击付款操作按钮时，通过向我们的 API 发出 POST 请求来初始化交易。将邮箱、金额和任何其他参数传递给初始化交易API接口。

如果 API 调用成功，我们将返回授权 URL，你将重定向到该授权，以便客户输入付款信息以完成交易。

重要提示

  1. amount 应位于 支持的货币 的子单元中。
  2. 我们使用上面表格中的cart_id作为我们的交易reference。你应该使用系统中的唯一交易标识符作为参考。
  3. 我们在 transaction_data 数组中设置 callback_url。如果你不这样做，我们将使用设置的 在你的仪表板上 或 在画布上。如果需要，在代码中设置它可以让你灵活地使用重定向URL
  4. 如果你未在仪表板或代码上设置回调 URL，则用户在付款后不会被重定向回你的网站。
  5. 你可以为测试交易设置测试回调 URL，为实时交易设置实时回调 URL。
<?php
$url = "https://api.paystack.co/transaction/initialize";

$fields = [
'email' => "customer@email.com",
'amount' => "20000",
'callback_url' => "https://hello.pstk.xyz/callback",
'metadata' => ["cancel_action" => "https://your-cancel-url.com"]
];

$fields_string = http_build_query($fields);


$ch = curl_init();


curl_setopt($ch,CURLOPT_URL, $url);
curl_setopt($ch,CURLOPT_POST, true);
curl_setopt($ch,CURLOPT_POSTFIELDS, $fields_string);
curl_setopt($ch, CURLOPT_HTTPHEADER, array(
"Authorization: Bearer SECRET_KEY",
"Cache-Control: no-cache",
));


curl_setopt($ch,CURLOPT_RETURNTRANSFER, true);


$result = curl_exec($ch);
echo $result;
?>

校验交易

如果交易成功，Paystack会将用户重定向回你设置的callback_url。我们将在 URL 中附加交易引用。在上面的示例中，用户将被重定向到http://your_website.com/postpayment_callback.php?reference=YOUR_REFERENCE。

因此，你从 URL 参数中检索引用，并使用它来调用校验接口来确认交易的状态。了解更多关于校验交易的信息。

在传递价值之前调用校验接口来确认交易的状态非常重要。仅仅因为callback_url被访问并不能证明交易成功。

手柄 Webhook

付款成功后，Paystack 会向你提供的 Webhook URL 发送charge.success Webhook 事件。了解有关使用 Webhook 的更多信息。

手机SDK

通过我们的移动设备SDK，我们提供了一系列适合平台美观的方法和界面。交易在服务端上发起并在SDK中完成。 SDK 需要 access_code 来显示受理支付的 UI 组件。

要获取 access_code，你需要通过在服务端上向 初始化交易API 接口发出 POST 请求来初始化交易：

curl https://api.paystack.co/transaction/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com",
"amount": "500000"
}'
-X POST
{
  "status": true,
  "message": "Authorization URL created",
  "data": {
    "authorization_url": "https://checkout.paystack.com/nkdks46nymizns7",
    "access_code": "nkdks46nymizns7",
    "reference": "nms6uvr1pl"
  }
}

交易成功初始化后，你会收到包含 access_code 的响应。你需要将此access_code返回到你的移动应用程序。

不要直接在你的移动应用程序上向初始化交易接口发出 API 请求，因为它需要你的密钥。你的密钥只能在可以采取更强安全措施的服务端上使用。

access_code就位后，你现在可以使用SDK来完成交易。

Android SDK

你需要通过将 paystack-ui 依赖项添加到应用程序级build.gradle文件的dependencies块来安装SDK：

安装前你应该检查梅文中心以获取最新版本。

  • 构建.gradle
dependencies {
implementation 'com.paystack.android:paystack-ui:0.0.9'
}

现在受理支付的所有要求都已到位，你可以初始化并使用 SDK，如下所示：


import com.paystack.android.core.Paystack
import com.paystack.android.ui.paymentsheet.PaymentSheet
import com.paystack.android.ui.paymentsheet.PaymentSheetResult

class MainActivity : AppCompatActivity() {
private lateinit var paymentSheet: PaymentSheet

override fun onCreate(savedInstanceState: Bundle?) {
super.onCreate(savedInstanceState)


Paystack.builder()
.setPublicKey("pk_test_xxxx")
.build()
paymentSheet = PaymentSheet(this, ::paymentComplete)

}

private fun makePayment() {

paymentSheet.launch("br6cgmvflhn3qtd")
}


private fun paymentComplete(paymentSheetResult: PaymentSheetResult) {
val message = when (paymentSheetResult) {
PaymentSheetResult.Cancelled -> "Cancelled"
is PaymentSheetResult.Failed -> {
Log.e("Something went wrong", paymentSheetResult.error.message.orEmpty(), paymentSheetResult.error)
paymentSheetResult.error.message ?: "Failed"
}

is PaymentSheetResult.Completed -> {

Log.d("Payment successful", paymentSheetResult.paymentCompletionDetails.toString())
"Successful"
}
}
}
}

你可以查看Android SDK 参考以了解有关可用于集成的方法和接口的更多信息。

iOS SDK

SDK的安装可以通过Swift 包管理器完成。要添加所需的软件包，请确保已安装 最新版本的 XCode 并按照以下步骤操作：

  1. 选择文件 > 添加包依赖项...
  2. 在包依赖弹出窗口的搜索框中复制存储库 URL 并粘贴它

你可以阅读 Swift 包管理器文档 了解有关向项目添加包的更多信息。

现在受理支付的所有要求都已到位，你可以初始化并使用 SDK：

import SwiftUI
import PaystackCore
import PaystackUI

struct PaymentView: View {
let paystack = try? PaystackBuilder
.newInstance
.setKey("pk_domain_xxxxxxxx")
.build()

var body: some View {
VStack(spacing: 8) {
Text("Make Payemnt")

paystack?.chargeUIButton(accessCode: "0peioxfhpn", onComplete: paymentDone) {
Text("Initiate Payment")
}
}
.padding()
}

func paymentDone(_ result: TransactionResult) {

print(result)
}
}

你可以查看iOS SDK 参考以了解有关可用于集成的方法和接口的更多信息。

充电API

创建电荷 API 接口允许你将任何支付渠道的详细信息以及交易详细信息（email、amount 等）直接传递到 Paystack。我们提供了几个 支付渠道，你可以根据你的用例进行利用。

使用案例

Charge API 暴露了为我们的结账提供动力的核心组件。开发人员可以使用这些组件来开发满足客户特定需求的解决方案。其中一些需求包括：

  1. 为非智能手机用户提供服务。你的某些用户可能使用无法访问互联网的手机。通过费用API，你可以从服务端发起付款请求，并通过电话号码向这些用户发送付款完成提示。
  2. 利用移动设备 OS APIs 获得更好的用户体验。一些企业通过移动应用程序（Android和iOS）提供产品。移动操作系统提供了一组丰富的APIs供开发人员利用。其中一个APIs允许开发人员在表单中自动填充OTP。还有用于拨号代码的APIs。开发人员可以将收费API与移动OSAPIs结合起来，为用户提供更丰富的体验。

以下是 Charge API 的示例有效负载，其中包含交易详细信息和支付工具的对象 - 在本例中为移动货币：

{
  "amount": 1000,
  "email": "customer@email.com",
  "currency": "GHS",
  "mobile_money": {
    "phone": "0553241149",
    "provider": "MTN"
  }
}

手续费API回复

当你调用 创建电荷 API 接口时，响应包含一个 data.status，它告诉你该过程的下一步是什么。根据 data.status 中的值，你可能需要提示用户输入响应消息中指示的内容（例如 OTP 或 PIN 码或出生日期），或显示用户需要在其设备上完成的操作 - 例如扫描 QR 代码或拨打 USSD 代码或重定向到 3DSecure 页面。因此，你按照data.status上的提示进行操作，直到不再需要用户输入，然后通过Webhook监听事件。

对于提示用户输入的步骤，你将需要向用户显示一个表单以收集请求的输入并将其发送到相关的接口，如下表所示。对于需要用户在设备上完成操作的步骤，我们建议你在用户执行该操作后显示一个确认付款的按钮，以便你可以通过 Webhook 监听事件。

以下是你可以从 创建电荷 API 接口收到的回复列表以及下一步应该做什么：

价值描述
pending交易正在处理中。获得此状态后至少 10 秒致电检查待处理费用以检查状态
timeout交易失败。向用户显示data.message后即可开始新的收费
success交易成功。你现在可以提供价值
send_birthday需要客户的生日才能完成交易。通过接受出生日期的输入向用户显示 data.display_text 并提交给 提交生日API 接口以及参考和生日
send_otpPaystack需要客户提供OTP才能完成交易。使用接受 OTP 的输入向用户显示 data.display_text，并将 OTP 提交给 提交 OTP API 接口以及引用和 otp
failed交易失败。对此没有补救措施，向用户显示 data.message 后开始新的收费

手柄 Webhook

付款成功后，Paystack 会向你提供的 Webhook URL 发送charge.success Webhook 事件。强烈建议你在向客户提供价值之前使用 Webhook 确认付款状态。

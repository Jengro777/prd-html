建立一个循环系统来接受多个客户的付款。

在接受客户的首次商品和服务付款后，你可以保存对回头客的付款授权。授权允许你构建自定义定期支付系统，而客户的干预最少。随着客户群的增长，构建定期支付系统的复杂性也会随之增加。

批量充电API 接口抽象了这些复杂性，为你提供了一个简单的交互界面。

它是如何运作的

当你有多个客户需要定期收费时，建议你针对每个请求发送一组费用，而不是针对每个费用发起一个请求。这是为了避免速率限制，同时确保随着业务的增长你拥有可扩展的系统。

批量充电API 接口适用于批次（批处理）和收费对象。批次由具有以下参数的电荷对象的集合组成：

参数需要吗？类型描述
amount是的整数向客户收取的金额。
authorization是的字符串之前完成的交易的授权码。
reference否字符串费用的唯一标识符。
attempt_partial_debit否布尔值一个标志，指示你是否希望我们在客户资金不足时尝试收回较低金额。
at_least否整数这与 attempt_partial_debit parameter 一起使用。它用于设置如果实际金额失败我们应该重试的金额。
metadata否对象这是为了保存付款后流程的自定义数据。

批量中的费用在接收时排队并定期处理。在处理过程中，如果收费失败，我们会将收费添加回队列以进一步重试。

下表显示了规划批次时需要牢记的指标：

公制价值描述
最大批量1000每个请求可以接受的费用总数。
重试限制5在标记为失败之前我们尝试处理费用的次数。

集成清单

批次中的费用数量取决于你的用例和规模，因此在规划批次时，请参考以下清单：

  • 确保你的批次大小在批次限制内。
  • 始终传递参考信息以轻松跟踪每笔费用。引用有助于实现幂等性，这样，如果你需要再次重试特定费用，就不会面临双重借记的风险。另外，在没有参考的情况下，不能批量使用相同的授权。如果你需要批量多次计费，请为每次计费传递一个参考。
  • 如果你的企业付款违约率较高，请传递attempt_partial_debit参数。
  • 构建重试逻辑时，使用 网关响应 解释 data 对象中的 gateway_response_code。对于客户错误，你需要联系他们来解决问题，而对于处理错误，你可以使用相同的参考重试。

创建批量收费

批次和费用设计就位后，你可以向 开始批量充电 API 接口发出 POST 请求，将每个费用对象传递给批次：

#!/bin/sh
url="https://api.paystack.co/bulkcharge"
authorization="Authorization: Bearer YOUR_SECRET_KEY"
content_type="Content-Type: application/json"
data='[
{
"amount": 10000,
"authorization": "AUTH_ncx8hews93",
"reference": "my_reference_1"
},
{
"amount": 15000,
"authorization": "AUTH_200nvt70zo",
"reference": "my_reference_2"
},
{
"amount": 25000,
"authorization": "AUTH_84bqxd3rkf",
"reference": "my_reference_3"
}
]'

curl "$url" -H "$authorization" -H "$content_type" -d "$data" -X POST

响应的data对象中的batch_code允许你跟踪和管理批次，因此建议你保存它以供以后使用。还有另外两个参数可以为你提供有关批次的更多详细信息：

  1. total_charges：这是批次中可用的收费对象的总数。
  2. pending_charges：这是剩余待处理的费用金额。

订阅 API 允许开发人员在其应用程序中嵌入定期计费功能，而无需自行管理计费周期。商户可以轻松创建计划并定期自动向客户收费。我们仅支持银行卡和直接借记卡（尼日利亚）。

设置订阅的方法如下：

  1. 制定计划
  2. 创建订阅
  3. 监听订阅事件

制定计划

计划是订阅的基础构建块。计划代表你销售的产品、销售价格以及收费频率。

你可以通过 PaystackDashboard 创建计划，或者通过调用 创建计划API 接口，传递：

参数类型描述
name字符串计划名称
interval字符串对该计划收取订阅费的时间间隔。可用选项有 hourly、daily、weekly、monthly、quarterly、biannually（每 6 个月）和 annually
amount整数收费金额
curl https://api.paystack.co/plan
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "name": "Monthly Retainer",
"interval": "monthly",
"amount": 500000
}'
-X POST
{
  "status": true,
  "message": "Plan created",
  "data": {
    "name": "Monthly Retainer",
    "interval": "monthly",
    "amount": 500000,
    "integration": 428626,
    "domain": "test",
    "currency": "NGN",
    "plan_code": "PLN_u4cqud8vabi89hx",
    "invoice_limit": 0,
    "send_invoices": true,
    "send_sms": true,
    "hosted_page": false,
    "migrate": false,
    "id": 49122,
    "createdAt": "2020-05-22T12:36:12.333Z",
    "updatedAt": "2020-05-22T12:36:12.333Z"
  }
}

按月间隔的订阅计费取决于创建订阅的月份日期。如果订阅是在当月 28 日或之前创建的，则在计划有效期内每月会在同一天计费。在 29 日至 31 日之间创建的订阅将在计划有效期内的每个后续月份的 28 日计费

你还可以传递 invoice_limit，它允许你设置可以在此计划中向客户收费的次数。因此，如果你在包月套餐中设置 invoice_limit: 5，那么客户将每月付费，为期 5 个月。如果你没有通过invoice_limit，我们将继续向客户收取费用，直至计划取消。

创建订阅

现在我们有了计划，我们可以继续下一步：为客户订阅该计划。我们可以通过多种方式创建新订阅。

  1. 将计划代码添加到交易
  2. 使用 创建订阅 API 接口

将计划代码添加到交易中

你可以使用 初始化交易API 接口为客户创建订阅，方法是将你创建的计划的 plan_code 添加到请求正文中。这将覆盖传递的交易金额，并向客户收取计划金额。

客户付款后，他们将自动订阅该计划，并根据计划中设置的时间间隔（和发票限额）进行计费。

curl https://api.paystack.co/transaction/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com",
"amount": "500000",
"plan": "PLN_xxxxxxxxxx"
}'
-X POST
{
  "status": true,
  "message": "Authorization URL created",
  "data": {
    "authorization_url": "https://checkout.paystack.com/nkdks46nymizns7",
    "access_code": "nkdks46nymizns7",
    "reference": "nms6uvr1pl"
  }
}

使用创建订阅接口

你还可以通过调用 创建订阅 API 接口，传递 customer 和 plan 来创建订阅。客户必须已经在你的 Paystack 集成上完成了交易。这是因为订阅 API 使用卡和直接借记授权向客户收费，因此需要有现有的授权才能收费。

如果客户有多个授权，你可以在创建订阅时通过将 authorization_code 传递为 authorization 来选择用于订阅的授权。否则，Paystack 会选择最近的authorization进行收费。

你还可以传递 start_date 参数，该参数可让你设置首次借记的日期。这使得此方法非常适合以下情况：你希望在开始向客户收费之前给他们一段免费时间，或者你想要将客户切换到其他计划时。

如果订阅收费失败，我们不会重试。订阅非常适合付款后交付价值的情况。例如互联网服务或流媒体服务的支付。

监听订阅事件

创建订阅将导致 Paystack 发送以下事件：

  1. 发送 subscription.create 事件表示已为付费客户创建了订阅。
  2. 如果你通过向交易添加计划代码来创建订阅，还会发送 charge.success 事件以指示交易成功。

每个后续计费周期都会发生以下步骤：

  1. 将发送 invoice.create 事件来指示将对订阅进行收费尝试。该信息将在下一个付款日期前 3 天发送。
  2. 如果收费尝试成功，则在下一个付款日期，将发送 charge.success 事件。如果没有，则会发送 invoice.payment_failed 事件。
  3. 尝试充电后将发送 invoice.update 事件。这将包含此订阅付款的发票的最终状态，以及收费信息（如果成功）

取消订阅也会触发事件：

  1. 将发送 subscription.not_renew 事件以指示订阅不会在下一个付款日期续订。
  2. 在下一个付款日，将发送subscription.disable事件，表明订阅已取消。

完成订阅的所有计费周期后，将发送最终 subscription.disable 事件，并将 status 设置为 complete。

管理订阅

你已经制定了计划，并开始向客户订阅这些计划。在本节中，我们将讨论如何管理这些订阅，以确保你不会错过付款，并且你的客户不会失去服务。

订阅状态是管理订阅的关键。每个状态都包含有关订阅的信息，让你知道是否需要采取行动来保留该客户。目前订阅有 5 种可能的状态。

状态描述
active订阅当前处于活动状态，将在下一个付款日期收取费用。
non-renewing订阅当前处于活动状态，但我们不会在下一个付款日期收取费用。当订阅即将完成或已取消（但我们尚未到达下一个付款日期）时，就会发生这种情况。
attention订阅仍然有效，但尝试向客户的卡收费时出现问题。问题可能是卡过期、资金不足等。我们将尝试在下一个付款日期再次向该卡收费。
completed订阅已完成，不再收费。
cancelled订阅已取消，我们将不再尝试通过订阅卡收费。

处理订阅付款问题

如上一节所述，如果订阅状态为attention，则表示尝试向客户的卡扣款时出现问题，我们无法成功扣款。

要解决此问题，你可以查看 获取订阅 API 响应正文中返回的 most_recent_invoice 对象。此对象包含有关最近尝试对订阅卡进行收费的信息。如果订阅的状态为 attention，则 most_recent_invoice 对象将有一个设置为 failed 的状态字段和一个描述字段，其中包含有关尝试向卡充值时出错的更多信息。

更新订阅

要更改订阅，你将使用 更新计划API 接口。你应该考虑是否要更改现有订阅或保持原样。例如，如果你要更新价格或收费间隔。你将使用 update_existing_subscriptions 参数来控制它：

  • 当设置为 true 时：所有订阅都将更新，并且更改将应用于下一个计费周期。
  • 当设置为 false 时：当前订阅将保持不变，只有新订阅才会跟随更新。

如果省略此参数，更新将自动应用于所有订阅。

更新订阅卡

当客户的订阅的卡或银行出现付款问题时，你可以生成指向托管订阅管理页面的链接，他们可以在其中更新其授权。在该页面上，你的客户可以选择添加新卡、直接借记账户或取消订阅。如果他们选择添加一张新卡，Paystack 会向该卡收取少量费用以将其代币化。不用担心，费用会立即退还。

curl https://api.paystack.co/subscription/:code/manage/link
-H "Authorization: Bearer YOUR_SECRET_KEY"
-X GET
{
  "status": true,
  "message": "Link generated",

如果你已经有一个页面供订阅者管理其订阅，你可以选择在该页面上添加一个按钮或链接来生成链接并将客户重定向到订阅管理页面。

或者，你可以触发 Paystack 向客户发送一封邮箱，其中包含链接。

curl https://api.paystack.co/subscription/:code/manage/email
-H "Authorization: Bearer YOUR_SECRET_KEY"
-X POST
{
  "status": true,
  "message": "Email successfully sent"
}

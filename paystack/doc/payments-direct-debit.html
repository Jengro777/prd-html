企业可以对客户的账户发起付款授权请求。一旦客户同意，该企业就可以定期从他们的账户中扣除费用。

直接借记是一种支付渠道，允许企业在获得客户同意后从客户的银行账户中扣除费用。在从客户的账户中扣除费用之前，他们需要获得与其联络的企业的同意。企业可以创建一项授权书，寻求客户的许可以借记其账户。

处理任务有三个独立的流程。使用“收费”在付款时设置授权，使用“设置授权”直接创建授权而无需付款，并使用“校验”随时检查授权的状态。

此功能仅适用于尼日利亚的企业。

通过收费创建授权

在一个流程中进行付款并设置授权。使用包含客户账户和地址的 direct_debit 对象向 创建电荷 API 接口发出 POST 请求：

#!/bin/sh
curl https://api.paystack.co/charge
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"email": "ravi@demo.com",
"amount": "1000000",
"currency": "NGN",
"direct_debit": {
"account": { "number": "0123456789", "bank_code": "057" },
"address": { "street": "126 Joel Ogunnaike", "city": "Ikeja", "state": "Lagos", "country": "NG" },
"phone": "+2348012345678"
}
}'
-X POST
{
  "status": true,
  "message": "Charge attempted",
  "data": {
    "reference": "dd-charge-8f3a1c",
    "status": "pending_bank_transfer",
    "amount": 1000000,
    "account_number": "1234567890",
    "bank_name": "Test Bank"
  }
}
领域必填注释
email是的客户邮箱。
amount是的整数，在 kobo 中表示 NGN。
currency否默认为集成的默认货币。
reference否你独特的参考。如果省略则自动生成。
direct_debit.account.number是的10 位帐号。
direct_debit.account.bank_code是的银行代码，例如057。
direct_debit.address.street是的街道。
direct_debit.address.city是的城市。
direct_debit.address.state是的状态。
direct_debit.address.country否国家。
direct_debit.phone否客户电话。

响应包括 pending_bank_transfer 状态以及 account_number、bank_name 和 amount。向客户提供这些详细信息以完成一次性转账。一旦我们收到转账，该任务就会生效。投票校验进行确认，或聆听Webhook。

初始化交易

或者，为客户设置授权的最快方法是将带有自定义过滤器的 bank 通道传递到 初始化交易API 接口：

curl https://api.paystack.co/transaction/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{ "email": "customer@email.com",
"amount": "10000",
"channels": ["bank"],
"metadata": {
"custom_filters": {
"recurring": true
}
}
}'
-X POST
{
  "status": true,
  "message": "Authorization URL created",
  "data": {
    "authorization_url": "https://checkout.paystack.com/zcwh3axoir37x7q",
    "access_code": "zcwh3axoir37x7q",
    "reference": "gz8nyit2zd"
  }
}

在完成交易的过程中，获得客户的同意，允许我们创建可用于后续付款的授权。仅当客户的账户属于直接借记的 支持的银行 范围内时，才会创建授权。你可以按照核实授权部分的步骤获取授权状态。

直接设置授权

要创建不付款的授权，请使用 初始化授权API 接口向客户发出授权请求：

#!/bin/sh
curl https://api.paystack.co/customer/authorization/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"email": "ravi@demo.com",
"channel": "direct_debit",
"callback_url": "http://test.url.com"
}'
-X POST
{
  "status": true,
  "message": "Authorization initialized",
  "data": {
    "redirect_url": "https://link.paystack.co/82t4mp5b5mfn51h",
    "access_code": "82t4mp5b5mfn51h",
    "reference": "dfbzfotsrbv4n5s82t4mp5b5mfn51h"
  }
}

响应包含一个 redirect_url，你可以重定向客户以同意你的请求。如果你在请求中提供了callback_url，客户将在同意后被发送到该页面。

为了获得更好的UI体验，你可以通过在请求中添加account和address对象来预先填写一些客户信息：

curl https://api.paystack.co/customer/authorization/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"channel": "direct_debit",
"email": "ravi@demo.com",
"callback_url": "http://test.url.com",
"account": {
"number": "0128034955",
"bank_code": "058"
},
"address": {
"state": "Lagos",
"city": "Akoka",
"street": "17 Beckley Avenue"
}
}'
-X POST

虽然 account 和 address 对象都是可选的，但在使用时，两个对象中的所有参数都是强制性的。 account对象中的bank_code代表客户的银行。

你还可以通过在同一请求中传递 use_hosted_url 来控制客户看到的授权设置体验。对于非托管流程，将其设置为 false，你可以自行执行设置步骤，或者对于托管流程，将其保留为 true（默认值），我们在redirect_url 上显示设置。由于 true 是默认值，因此现有托管集成不受影响。

curl https://api.paystack.co/customer/authorization/initialize
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"channel": "direct_debit",
"email": "ravi@demo.com",
"use_hosted_url": false
}'
-X POST

对于非托管流，响应包含 mandate 对象和 transferDetails 而不是 redirect_url：

{
  "status": true,
  "message": "Authorization initialized",
  "data": {
    "reference": "54eyym8uf802ycx",
    "mandate": {
      "id": 3315722,
      "status": "pending",
      "isNew": true
    },
    "transferDetails": {
      "amount": "50.00",
      "account_number": "9880218357",
      "account_name": "NIBSS DIRECT DEBIT",
      "bank_name": "Paystack-Titan"
    },
    "status": "pending_bank_transfer"
  }
}

向客户出示transferDetails即可完成一次性转账。一旦我们收到转账，该任务就会生效。投票校验进行确认，或聆听Webhook。

校验

随时检查任务的状态或费用的状态。

校验授权

我们将以下 Webhook 事件发送到你的 Webhook URL 以传达客户授权的状态：

活动描述
direct_debit.authorization.created当客户批准你的授权请求时发送此信息。这并不意味着客户的账户已准备好收费。
direct_debit.authorization.active当客户的授权处于活动状态且可以向其账户收费时发送此信息。
{
  "event": "direct_debit.authorization.created",
  "status": true,
  "message": "Authorization retrieved successfully",
  "data": {
    "authorization_code": "AUTH_JV4T9Wawdj",
    "active": false,
    "last4": "1234",
    "channel": "direct_debit",
    "card_type": "mandate",
    "bank": "Guaranty Trust Bank",
    "exp_month": 1,

    "country_code": "NG",
    "brand": "Guaranty Trust Bank",
    "reusable": true,
    "signature": "SIG_u8SqR3E6ty2koQ9i5IrI",
    "account_name": "Ravi Demo",
    "customer": {
      "first_name": "Ravi",
      "last_name": "Demo",

      "email": "ravi@demo.com",
      "phone": "",
      "metadata": null,

    }
  }
}

或者，你可以通过使用初始化请求中的引用向 校验授权API 发出请求来确认授权状态。

#!/bin/sh
curl https://api.paystack.co/customer/authorization/verify/:reference
-H "Authorization: Bearer YOUR_SECRET_KEY"
-X GET
{
  "status": true,
  "message": "Authorization retrieved successfully",
  "data": {
    "authorization_code": "AUTH_JV4T9Wawdj",
    "channel": "direct_debit",
    "bank": "Guaranty Trust Bank",
    "active": true,
    "customer": {
      "code": "CUS_24lze1c8i2zl76y",
      "email": "ravi@demo.com"
    }
  }
}

如果授权尚未获得批准或者你在创建授权之前尝试进行校验，你将收到 404 error，响应如下所示：

{
  "status": false,
  "message": "Authorization does not exist or does not belong to integration",
  "metadata": {
    "nextStep": "Try again later"
  },
  "type": "api_error",
  "code": "unknown"
}

当调用校验授权接口时，你将受到我们的速率限制规则的约束。

在某些情况下，授权可能会陷入 pending 状态。在这种情况下，你可以向客户收取激活费用：

#!/bin/sh
curl https://api.paystack.co/customer/{id}/directdebit-activation-charge
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"authorization_id" : 1069309917
}'
-X PUT
{
  "status": true,
  "message": "Mandate is queued for retry"
}

对于多个客户，你可以使用 直接借记激活费用 API 接口，如下所示：

#!/bin/sh
curl https://api.paystack.co/directdebit/activation-charge
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"customer_ids": [28958104, 983697220]
}'
-X PUT
{
  "status": true,
  "message": "Mandate is queued for retry"
}

此请求将导致从客户的账户中扣除NGN50，以便我们确认是否可以从客户的账户中扣除。但是，一旦我们完成检查，这笔费用就会退还。

经常性费用

客户批准授权后，我们会提供 authorization_code，你可以使用该authorization_code定期从其账户中扣除费用。你可以通过将 authorization_code 与匹配的 email 传递到 充电授权API 接口来借记客户的账户。

停用授权

你可能需要在交易完成后或根据客户的请求停用授权。为此，请向 停用授权API 发出 POST 请求：

#!/bin/sh
curl https://api.paystack.co/customer/authorization/deactivate
-H "Authorization: Bearer YOUR_SECRET_KEY"
-H "Content-Type: application/json"
-d '{
"authorization_code": "AUTH_xxxIjkZVj5"
}'
-X POST
{
  "status": true,
  "message": "Authorization has been deactivated"
}

Webhook 事件

Webhook 事件 API 让你可以查看事件与服务端响应，并重发发送到你的集成（各[环境]）的 Webhook 事件。

查询 Webhook 事件列表

GET /integration/webhooks/events

分页获取集成中的 Webhook 事件列表，可按分类、事件类型、状态、资源 ID 或日期筛选。

请求头（Headers）

authorizationString必填

取值设为 Bearer SECRET_KEY

查询参数（Query Parameters）

categoryString可选

按分类筛选，例如 transactions

event_typeString可选

按事件名称筛选，例如 charge.success

statusString可选

按配送状态筛选，取值为 Delivered，Pending，Failed

category_row_idString or Integer可选

按底层资源 ID 筛选，例如交易 ID

fromDatetime可选

开始列出 Webhook 事件的起始时间，例如 2016-09-24T00:00:05.000Z，2016-09-21

toDatetime可选

停止列出 Webhook 事件的结束时间，例如 2016-09-24T00:00:05.000Z，2016-09-21

limitInteger可选

每页返回的事件数，默认 20

nextString可选

来自上一次响应的游标：meta.next，用于获取下一页。请不要与 previous

previousString可选

来自上一次响应的游标：meta.previous，用于获取上一页。请不要与 next

请求示例cURL
#!/bin/sh
url="https://api.paystack.co/integration/webhooks/events?status=Failed&limit=50"
authorization="Authorization: Bearer YOUR_SECRET_KEY"

curl "$url" -H "$authorization" -X GET
响应示例JSON
{
  "status": true,
  "message": "Webhooks listed",
  "data": [
    {
      "_id": "665f1c2a9d1e4b0012a3c4d5",
      "domain": "live",
      "category": "transactions",
      "event_name": "charge.success",
      "category_row_id": 4045667488,
      "status": "Failed",
      "status_detail": "retrying",
      "response_code": 500,
      "trial_count": 3,
      "createdAt": "2026-07-09T15:17:00.000Z",
      "updatedAt": "2026-07-09T15:42:00.000Z"
    }
  ],
  "meta": {
    "next": "cursor_next",
    "previous": null,
    "perPage": 50
  }
}

检索 Webhook 事件

GET /integration/webhooks/events/lookup

通过交易 ID（注意不是交易 reference）或事件 ID 查找 Webhook 事件。

请求头（Headers）

authorizationString必填

取值设为 Bearer SECRET_KEY

查询参数（Query Parameters）

referenceString必填

要检索的交易 ID 或事件 ID（不是交易 reference）。事件 ID 会直接匹配，其他值将按底层交易 ID 匹配

请求示例cURL
#!/bin/sh
url="https://api.paystack.co/integration/webhooks/events/lookup?reference=4045667488"
authorization="Authorization: Bearer YOUR_SECRET_KEY"

curl "$url" -H "$authorization" -X GET

查询 Webhook 事件

GET /integration/webhooks/events/{id}

查询单个 Webhook 事件的完整详情，包括发送的 payload 以及你的接口返回的响应。

请求头（Headers）

authorizationString必填

取值设为 Bearer SECRET_KEY

路径参数（Path Parameters）

idString必填

事件的 _id，来自列表项的

请求示例cURL
#!/bin/sh
url="https://api.paystack.co/integration/webhooks/events/665f1c2a9d1e4b0012a3c4d5"
authorization="Authorization: Bearer YOUR_SECRET_KEY"

重发 Webhook 事件

POST /integration/webhooks/events/resend

重发指定的一组 Webhook 事件到你当前的 Webhook 地址。重发不是幂等的 —— 同一事件 ID 提交两次会投递两次。

请求头（Headers）

authorizationString必填

取值设为 Bearer SECRET_KEY

content-typeString必填

取值设为 application/json

请求体参数（Body Parameters）

idsArray必填

非空的事件数组 _id（要重发的事件），单次请求最多 100 个

请求示例cURL
#!/bin/sh
url="https://api.paystack.co/integration/webhooks/events/resend"
authorization="Authorization: Bearer YOUR_SECRET_KEY"
content_type="Content-Type: application/json"
data='{
"ids": ["665f1c2a9d1e4b0012a3c4d5", "665a0b119d1e4b0012a3bd90"]
}'

curl "$url" -H "$authorization" -H "$content_type" -d "$data" -X POST
响应示例JSON
{
  "status": true,
  "message": "Resend accepted",
  "data": {
    "count": 2,
    "failed": 0,
    "failed_ids": []
  }
}

重发匹配的 Webhook 事件

POST /integration/webhooks/events/resend-matching

重发所有符合筛选条件的 Webhook 事件。建议先传 preview=true 确认匹配数量后再执行重发。

请求头（Headers）

authorizationString必填

取值设为 Bearer SECRET_KEY

content-typeString必填

取值设为 application/json

查询参数（Query Parameters）

previewBoolean可选

设为 true（仅返回匹配数量，不实际重发）

请求体参数（Body Parameters）

filtersObject可选

与以下接口相同的筛选条件：查询 Webhook 事件列表：category，event_type，status，category_row_id，from，to。均为可选。

请求示例cURL
#!/bin/sh
url="https://api.paystack.co/integration/webhooks/events/resend-matching"
authorization="Authorization: Bearer YOUR_SECRET_KEY"
content_type="Content-Type: application/json"
data='{
"filters": {
"status": "Failed",
"category": "transactions",
"event_type": "charge.success",
"from": "2026-07-01",
"to": "2026-07-09"
}
}'

curl "$url" -H "$authorization" -H "$content_type" -d "$data" -X POST
响应示例JSON
{
  "status": true,
  "message": "Preview",
  "data": {
    "count": 128
  }
}
